# zero-core-surface.txt — the ONE declaration both guards over the zero-core
# vocabulary invariant read (#311, #324).
#
# ── WHY THIS FILE EXISTS ────────────────────────────────────────────────────────
# Two guards enforce ONE invariant — "the app core never learns the domain":
#
#   * scripts/check-derived-vocabulary.sh — fast, dialect-aware, tiered; runs in a
#     second as a leg of `just check-guards`;
#   * src-app/packages/spatial-types/tests/test_spatial_types_manifest.py's
#     test_a_new_kind_costs_zero_core_code — wholesale, raw-text, zero-tolerance.
#
# They derived their SURFACE and their EXEMPTION RULE separately, so they could
# disagree — and twice they did. #303: a leak in a `scripts/*.mjs` guard that the
# shell guard did not scan and the pytest did. #324: a leak in
# src-app/libs/viz/scripts/, which is inside the pytest's surface and was outside the
# shell guard's, because #304 had widened that guard to "all of scripts/" meaning the
# REPO ROOT. In both cases the fast guard printed PASS and the slow one carried the
# red to `main`.
#
# docs/design/derived-guards.md §2 says a guard derives the set it ranges over from
# the declaration that defines that set. §7.1 records that a scanned SURFACE is such
# a set, and that a glob typed into a guard drifts exactly the way a term list does.
# There was no product declaration of "what is build tooling" to derive from, so this
# file IS that declaration — and being ONE file that BOTH readers consult is the
# property that stops the two drifting apart again (#311's own prescription:
# "A shared declaration (a committed file both read) is the shape §2 asks for").
#
# ── WHAT BOUNDS IT ──────────────────────────────────────────────────────────────
# This file is PINNED in scripts/guard-hashes.txt, exactly like the guards that read
# it. Moving the surface or the exemption rule therefore costs a visible diff HERE
# and a re-pin diff THERE, in the same commit, with a human on the other side of it.
# That is the only property this machinery has ever had — check-guard-integrity.sh
# says so about itself: "not 'guards are immutable'; it is 'a guard cannot be
# weakened SILENTLY'" — and putting the surface in an UNPINNED data file would have
# removed it, which is why the file lives under scripts/lib/ (guard LOGIC, pinned for
# what it does rather than for what it is called).
#
# ── GRAMMAR, AND WHY EVERY VALUE IS A BORING TOKEN ──────────────────────────────
#   <field> <value>[ <rest of line>]
# One record per line. A line whose first non-blank character is `#` is a comment; a
# `#` anywhere else is DATA (issue numbers live in the reason text, so a mid-line
# comment rule would eat them). Blank lines are ignored.
#
# EVERY VALUE IS VALIDATED AGAINST A STRICT CHARSET, AND ANYTHING ELSE IS REFUSED.
# This is not tidiness; it is the repair for a demonstrated FAIL-OPEN. These values
# are interpolated into four different matcher languages — an awk ERE, a BRE `grep`,
# a Python `re`, and a git PATHSPEC — and a blind audit defeated every one of them
# from this file alone:
#   * `vocab_block_open txr:guard-vocabulary(` made awk's dynamic regex fail to
#     compile. awk compiles it lazily, on the first BUILD file, so awk died on EVERY
#     build file with its stderr swallowed, the guard read "no hits", and it printed
#     PASS over a real planted leak while still reporting 53 files scanned;
#   * `surface_root :(exclude)justfile` is a git PATHSPEC, not a path: git exits 0
#     with empty output and the recipes drop out of the surface, at exit 0;
#   * `surface_exception src-app/x+y` was escaped ERE-style and consumed by a BRE
#     `grep`, so `\+` became an OPERATOR: the declared directory was NOT exempted and
#     a DIFFERENT one (`src-app/xxy`) silently was;
#   * `surface_exception src-app/a(b` made the "names a real path" check itself
#     error out, so the check did not fire.
# A charset that admits none of those needs no escaping in any of the four languages,
# and both readers then agree by CONSTRUCTION rather than by two matching escapers.
# The charsets, enforced identically in both readers, fail-closed:
#   path values  (scan_root, surface_root, surface_exception, vocab_block_pins):
#                [A-Za-z0-9_./-]+ , no leading `-` or `.`, no `..` segment
#   name values  (surface_dir, test_path_segment): [A-Za-z0-9_.-]+ , one segment
#   marker values(vocab_block_open, vocab_block_close): [A-Za-z0-9:_-]+
# Both readers also FAIL CLOSED on a missing field, a duplicated single-valued field,
# an unparseable line, or a path that names nothing — a declaration that half-reads is
# a guard that scans less while reporting green.

# ── the SCAN ROOTS: the region both guards range over ───────────────────────────
# `scan_root` — a tracked path (file or directory) that is in scope for this
# invariant at all. The wholesale pytest scans exactly these, less the exclusions
# below; the fast guard's build tier is a SUBSET of them. Declaring them once is what
# makes "the fast guard can never outrun its backstop" checkable instead of hoped for
# (TEST-24), and it is why a `scripts/` directory somewhere neither guard has ever
# looked — `docs/scripts/`, say — is out of scope for BOTH rather than in scope for
# one. `docs/`, `.lifecycle/` and the submodules are outside these roots and are
# therefore not scanned; a submodule is one gitlink entry, not its contents, so its
# own tooling belongs to its own repository.
scan_root src-app
scan_root scripts
scan_root justfile

# ── what is never a SURFACE, in either guard ────────────────────────────────────
# `data_root` — a path that is the DATA this invariant is about, not a surface that
# could violate it. `check-derived-vocabulary.sh`'s header states the reason and it
# is a category error rather than an allowance: "a CONTRIBUTED processor package —
# the DATA. Not a surface at all, so the manifests can never be scanned against
# themselves … and a domain package's own domain vocabulary is exactly what it is
# FOR." The pytest already dropped this prefix; the fast guard dropped it on its
# app-core tier and, until a blind audit found it, NOT on the widened build tier — so
# a package that shipped a `scripts/` directory would have had its own declared id
# reported as a leak, which is §1's "starts refusing things it never meant to
# refuse", landing on exactly the act INV-3 exists to keep free.
data_root src-app/packages

# ── test code, excluded by the SAME list in both readers ────────────────────────
# `test_path_segment` — a path segment that marks test code. A test may legitimately
# name an id; a dispatch cannot be reached from one. The two readers kept two lists
# (the shell three segments, the pytest four), which is #311 residual 2's path-segment
# half; they are one list here.
#
# THE LIST IS THREE, AND THE FOURTH IS THE LESSON. The first cut unified on the LONGER
# list, adding `__tests__` on the argument that one list removes a way for the readers to
# disagree — true, and measured to change nothing in this tree, which was also true and was
# the problem. `__tests__` matched ZERO tracked files, so one of the four capped slots cost
# nothing to spend: a blind round re-pointed it at a directory holding a real planted leak
# and BOTH guards went green, with the record count never moving and the cap never firing.
# A capped exemption slot that classifies nothing is an exemption already paid for.
# MEASURED 2026-09-07: `tests` 1270 files, `fixtures` 360, `testdata` 2, `__tests__` 0.
#
# The BASENAME half of residual 2 is deliberately still open (`foo.test.ts` is a test
# module by name, on no test path). It is NOT closed here because one of #324's three
# leak sites was exactly such a file, and an exemption whose first act is to cover the
# defect that motivated the branch is what derived-guards.md §5 refuses. See #325.
#
# THIS IS AN EXEMPTION AXIS, AND IT IS BOUNDED LIKE ONE. For two rounds it was not, and a
# blind round showed the cost in one line: with a real leak planted at
# src-app/libs/viz/scripts/, appending `test_path_segment viz` here turned the fast guard, the
# wholesale scan AND the containment assertion green, for the price of a single re-pin --
# CHEAPER than adding a `surface_exception`, which additionally costs an edit to a second
# pinned file. An exemption axis priced below the one the guard advertises as capped is
# derived-guards.md §5's "widening an allowlist" wearing a different field name.
#
# Two things bound it now, and neither is prose:
#   * MAX_TEST_SEGMENTS in check-derived-vocabulary.sh caps the COUNT, so a fourth record costs
#     the same two committed diffs a sixth `surface_exception` costs;
#   * NEITHER READER APPLIES THESE SEGMENTS TO THE BUILD SURFACE. Build tooling is build
#     tooling wherever it sits; the exclusion that tier legitimately needs is the DERIVED
#     js-test one (the justfile's own `node --test` declarations), which no edit to this file
#     can re-point. The fast guard FAILS if a declared segment matches a build file at all,
#     and the wholesale side's containment assertion (TEST-24) reddens for the same reason
#     from the other direction. That is what actually kills the `viz` vector.
#
# WHAT IS STILL UNBOUNDED, said plainly: a segment appearing ONLY in the app-core tree
# (`viz-core`, say) removes app-core files and no build files, so only the cap and the byte
# pin stand between it and a silenced region -- the same residual an existing
# `surface_exception` has, since nothing decidable stops a record being re-pointed. #325.
test_path_segment tests
test_path_segment testdata
test_path_segment fixtures

# ── the BUILD-TOOLING surface ───────────────────────────────────────────────────
# `surface_root` — a tracked path that is build tooling wherever it sits.
# `surface_dir`  — a directory NAME. Every file git tracks under a directory of that
#                  name, at ANY depth WITHIN THE SCAN ROOTS, is build tooling. This is
#                  the STRUCTURAL fact #304 reached for the repo root and then wrote
#                  down as a root-only pathspec: being under `scripts/` is what makes
#                  a file part of the tooling, and that is as true of
#                  src-app/libs/viz/scripts/ as it is of the repo root. A `scripts/`
#                  directory nobody has created yet is scanned the day it lands inside
#                  the scan roots, with zero edits here — which is the difference
#                  between a derivation and the enumeration #324 fell through.
#
# A `surface_root` may NOT sit at or under a `data_root`: the exclusion would then remove
# everything it contributes, leaving a declared surface that scans nothing while every guard
# reports the same PASS. Both readers refuse the pair -- §3's "a marker naming nothing",
# found blind by appending such a root and watching the build count not move.
surface_root justfile
surface_dir scripts

# ── the written exceptions, what they cost, and why they are FILES ──────────────
# `surface_exception <path> <reason>` — a path the `surface_dir` rule would otherwise
# sweep in, excluded deliberately. The default is SCANNED: a new `scripts/` directory
# needs no entry here and is covered on arrival. An exception is the only thing anyone
# has to write down; it must NAME A REAL PATH inside a `surface_dir` (derived-guards.md
# §3: "A marker naming nothing is not 'a branch whose premise does not hold' — it is a
# guard switched off, and it looks identical from the outside"), and the number of them
# is CAPPED in the guard, so one more than the cap cannot be added without editing a
# second pinned file in the same commit.
#
# THESE ARE FILES, NOT A DIRECTORY PREFIX, AND THE DIFFERENCE IS THE WHOLE POINT.
# The first cut excepted `src-app/ui/scripts` wholesale. Measured, that excluded 66
# files to cover hits in 5 — 13x wider than its need — and a blind audit planted a leak
# in a sixth file there and reproduced the #324 STATE at a committed path: fast guard
# PASS, wholesale pytest RED, `just check-guards` green. A prefix exemption is §5's
# second bullet in substance even when its reason is sound, so the reason is applied to
# the files it is actually about and the other 61 are scanned like any build tooling.
# (The three numbers above were 66/2/64 for two rounds, written when there were two
# entries and left standing over five. Re-measured 2026-09-07: 66 tracked, 5 excepted,
# 61 scanned.)
#
# What each is, MEASURED 2026-09-07 by removing each entry ON ITS OWN and re-running (all
# five at once truncates against the guard's own 100-line report cap, which is how the first
# measurement of this came out wrong). Every one of the five is load-bearing: removing any
# single entry turns the guard RED naming exactly that file.
# ALL FIVE, and the reason this list is exhaustive rather than illustrative: an earlier cut
# enumerated two of them under a sentence beginning "Both are", which is how a reader learns
# there are two. Each entry's own record below carries its reason; the categories are:
#   * lint-no-domain-in-builtin.mjs — the SIBLING GUARD, which must SPELL what it hunts;
#   * domain-baseline.json — that guard's committed per-(file,token) ratchet BASELINE, a
#     record of the hits it tolerates, which cannot exist without spelling them;
#   * lint-no-domain-in-builtin.test.mjs and capture-surface-baseline.test.mjs — its two
#     control suites, JS test modules the justfile does not declare (the ui workspace runs
#     them), so the derived js-test-module exclusion cannot see them;
#   * surface-baseline-expected-delta.json — that control suite's committed expected-delta
#     fixture, which QUOTES the ids whose removal it asserts.
# Every one of the five is a GUARD's own data or a guard itself, the same category as
# `data_root` above, and scanning them is derived-guards.md §5's cry-wolf class.
#
# WHAT THIS STILL COSTS, said plainly: a ui control suite that legitimately plants
# vocabulary tomorrow will be reported, because the js-test-module derivation reads the
# JUSTFILE's `node --test` declarations and not the ui workspace's own. That is the
# repair #325 names, and it is what would retire all five entries below.
surface_exception src-app/ui/scripts/lint-no-domain-in-builtin.mjs the SIBLING GUARD over this same invariant, which must SPELL the vocabulary it hunts (#304's case). It cannot use a txr:guard-vocabulary block: check-guard-integrity.sh deliberately does NOT pin it (its own header says so — it is under active ratchet development by its owner), and a marker in an unpinned file is a hard failure by design. See #325.
surface_exception src-app/ui/scripts/domain-baseline.json that guard's committed per-(file,token) ratchet BASELINE — a record of the hits it tolerates, which cannot exist without spelling them. Its DATA, the same category as data_root. See #325.
surface_exception src-app/ui/scripts/lint-no-domain-in-builtin.test.mjs that guard's control suite: it PLANTS the vocabulary it asserts the guard reports. A JS test module the ui workspace declares rather than the justfile, so the derived js-test exclusion cannot see it. See #325.
surface_exception src-app/ui/scripts/capture-surface-baseline.test.mjs the surface-baseline control suite, same shape and same reason as the line above. See #325.
surface_exception src-app/ui/scripts/surface-baseline-expected-delta.json that control suite's committed expected-delta fixture — it QUOTES the ids whose removal it asserts, so it cannot exist without spelling them. Its DATA, same category as the baseline above. See #325.

# ── the DECLARED self-reference exemption (#304) ────────────────────────────────
# A sibling GUARD must SPELL the vocabulary it HUNTS (check-kinds-zero-core.sh's
# KINDS=, check-no-legacy-wire.sh's DOMAIN_REGEX=), and a guard that DISPATCHES on a
# domain id is the opposite case. Nothing can tell them apart from the outside, so
# the file says which it is doing, in its own bytes:
#
#     # txr:guard-vocabulary
#     KINDS=<the terms this guard hunts>
#     # txr:end-guard-vocabulary
#
# (`// txr:guard-vocabulary` in a .mjs.) TWO keys, both committed: the block, and
# the file being PINNED in the manifest named below. What bounds the block is the
# PIN, not a pattern — three attempts to bound it syntactically were each defeated in
# one line, and §7.1 records why there is no predicate any more.
#
# #311's residual 1 was that only ONE of the two guards honoured this. A guard that
# legitimately hunted a spatial id would pass the shell guard and FAIL the pytest,
# which granted no exemption at all — derived-guards.md §1's "starts refusing things
# it never meant to refuse", which it insists is the SAME failure as a vacuous green.
# Both readers now honour the same block on the same two keys, read from here — and
# the marker charset above is what makes "the same" true of the MATCHING and not only
# of the bytes.
vocab_block_open txr:guard-vocabulary
vocab_block_close txr:end-guard-vocabulary
vocab_block_pins scripts/guard-hashes.txt
