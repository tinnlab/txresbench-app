# The PINNED direct dependency set of the `single-cell` analysis env (#80 / DEC-2).
#
# THIS FILE IS THE SOURCE OF TRUTH for "what is installed in the analysis env". It is
# read by three consumers, so its shape is a contract, not a style:
#
#   1. the recipe — `Dockerfile` installs `uv pip install --no-cache -r requirements.txt`;
#   2. the BUILD GATE — `server/build_helper/processor_manifest.rs` resolves every
#      `run.dependencies[]` a package manifest declares against these pins, so a package
#      declaring a library that is absent here, or a version range these pins fall
#      outside, fails `cargo check` rather than a user's sandbox job (#80 defect 3);
#   3. the smoke-line gate — `sandbox::env_image::every_env_recipe_smoke_verifies_every_pinned_import`
#      asserts every line below is covered by the Dockerfile's build-time import smoke
#      line ("an install the smoke line does not verify silently ships absent"). It runs
#      over EVERY recipe `discover_env_recipes` finds, not this one, and it locates the
#      smoke line by the `# cyto:env-smoke` marker the Dockerfile puts above it — which is
#      why the `# import=` token below is required of every pin in every recipe: it is the
#      key the check is made on. (#196 moved this claim here from one analysis package's
#      test directory, where it named a single recipe and left any second one unguarded.)
#
# ── LINE FORMAT (enforced by the gate, not by convention) ────────────────────────────
#     <pypi-distribution>==<exact version>   # import=<module> — <why it is here>
# EXACT pins only. A bare name, a range, a duplicate distribution or a missing
# `import=` token is a BUILD ERROR. `import=` names the module the smoke line must
# import, because a distribution name is not an import name (`scikit-learn`→`sklearn`,
# `scikit-misc`→`skmisc`, `umap-learn`→`umap`).
#
# ── WHY EXACT PINS (the position, in one paragraph) ──────────────────────────────────
# Before #80 exactly one package here was pinned — `harmonypy==2.0.0` — with a comment
# explaining that its defaults are version-unstable, so the consuming analysis passes
# every parameter explicitly AND pins AND records the resolved version. That reasoning is
# not specific to harmonypy; it is the general case. Everything else resolved to whatever
# PyPI served on the day the image was built, which means a published result rested on a
# dependency version that appears in NO diff in this repo. A range would not fix it (two
# builds a month apart still land on different versions inside the range); only an exact
# pin does. The full TRANSITIVE closure is not pinned here — it is frozen INTO the image
# at `/opt/venv/.cyto-env-lock.txt` (148 distributions as built) and recorded per run, so
# transitive drift is visible in the provenance record of the run it affected instead of
# being invisible. The escalation conditions for promoting that freeze to a committed
# hash-pinned lockfile are in the runbook.
#
# ── UPGRADING A PIN ─────────────────────────────────────────────────────────────────
# Do NOT edit a version here without following `docs/runbooks/env-image-republish.md`
# §"Upgrading a pin". A pin change is invisible to every deployment until the image is
# REPUBLISHED (the runtime lazy-fetches the moving `schema<N>-latest-<arch>` tag), and it
# can invalidate a version range some package already declares — the build gate tells you
# which, mechanically, but only if you run it.
#
# Resolved by `uv pip compile --python-version 3.11` on 2026-09-02 (DEC-3). Pinning to the
# resolution of the day makes the pin a NO-OP for a fresh build: it freezes what was
# already shipping rather than moving anything.
#
# ── THE PACKAGING ECOSYSTEM AND THE PIN SOURCE, DECLARED (#192) ─────────────────────
# The two directives below say, machine-readably, what this file already said in prose:
# which packaging ecosystem it is (from which the gate derives BOTH the PEP 503
# distribution-name fold and the PEP 440 version grammar), and what its pins were
# resolved against.
#
# They are here even though nothing about this recipe's behaviour changes, and that is the
# point. "Every recipe declares its ecosystem and its pin source" is only a floor against
# a DELETED declaration if it is required of every recipe; an exemption for the one that
# happens to match the old default is exactly the silent case it exists to catch
# (`docs/design/derived-guards.md` §4). It also makes visible that the regime is not
# R-specific — the R recipe differs in its ANSWERS, not in being asked.
#
# `immutable-index`: a PyPI release is immutable and stays fetchable, so `<name>==<version>`
# denotes one artifact forever. That is the strongest of the classes the regime knows
# apart from a dated snapshot, and it is why the transitive-closure caveat below is about
# what was NOT pinned rather than about what a pin means.
# cyto:ecosystem=python
# cyto:pin-source=immutable-index:https://pypi.org/simple
