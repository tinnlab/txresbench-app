The Visualize pane

The pane exists, renders, and is empty — nothing in the codebase contributes to it, and a processor package has no way to. This proposes what fills it, and what a single-cell project looks like when it does.

One contribution kind, one canvas key. A package declares a section: a normal declarative view spec with no owning analysis, bound to data by capability rather than by producer. Sections stack inside the one pane and the user drags them into order. Nothing gains a pane; the centre canvas stays reserved.

The coordinate set IS the choice — there is no row-space question Superseded 2026-08-13 (owner). This pane opened with a Row space block above Coordinates. It is deleted: an axis is not a thing anybody picks, and the words do not exist in the owner's vocabulary. Coordinates is the pane's first block, it lists with nothing chosen first, and which rows is DERIVED from the set you pick — Dataset 1's UMAP and the integration's UMAP are simply two entries under two headings. The heading is dropped when there is only one dataset.

Sections stack and reorder Each is an independent contribution with its own store. The grip is the drag handle; order persists per project. A section installed later sorts to the end rather than being frozen out.

Only 2-D sets are listed Divergence, recorded 2026-08-13 (owner). This block used to list PCA as a third option. A decomposition declares fifty components and this pane draws in two, so offering it means either a component picker or a silent "first two" — layouts[0] wearing a default. A set declaring more than two components is not offered at all. Do not restore PCA here; ui/coordinates.yaml records the same divergence beside its dims: 2.

The coordinate is a radio One at a time. It says which points, positioned how — the frame every plot below is drawn in, and the rows every section below is scoped to.

Colour by and Features EMIT The button on the right puts a cell on the canvas. Two clicks, two cells: the same coordinate plotted two ways, side by side. The pane is not holding one current colouring — it is a launcher, and the canvas holds the result.

Features group by what the axis declares Uniqueness holds WITHIN a modality and deliberately not across, so RNA CD3 and ADT CD3 are both CD3 — and the group heading carries the difference instead of a per-row qualifier. It also makes a 137-entry protein panel findable beside 18,204 genes. One group ⇒ no heading. The storage index carries a CD3‑1; it must never be shown.

A feature has several names The header picks which annotation is shown; search matches all of them, and a row says which one it matched. The entry key is the identity — a symbol is a label, and symbols are reused.

Every row states its shape A categorical shows its level count, a continuous its range — the two facts that decide whether a column is worth plotting. Both are read from the catalog summary, never by downloading the column; a producer that declared neither says so, and is never scanned to fill a list.

Categorical before continuous A categorical column answers what are the groups — the question people open the pane with. Continuous is usually the QC follow-up. The ordering is the package's to declare, not the engine's to assume.

The ? marks unverified alignment No producer declares alignment yet, so this is the migration state, not a permanent tier. It is offered but never pre-selected, and the mark follows the choice into the legend.

Content is a real single-cell shape: two datasets, an integration run, and the columns that survive the union.

Why the integration can be coloured at all

cell_type exists in both datasets, so every cell in the integrated embedding has a value — ds1's cells from ds1's column, ds2's from ds2's. Coverage is complete, by union. A ds1‑only column is the different case, where half the points have nothing.

The pane does not guess which situation it is in. The integrator already computes the union alignment and already stamps coverage into the artifact's metadata, so coverage.missing == 0 is the machine-checkable boundary between the two. The producer measured it; the viewer reads it.

Same name, different kind, is two columns. If ds1's cell_type is categorical and ds2's is continuous, they do not compose — neither coercion is honest. Categorical → continuous invents an ordering the data has no claim to; the reverse invents bin edges nobody chose. The pane offers both, distinguished by kind, and says why they are not one option.

The rule underneath all of it

A name is not an identity. Six defects found in one sweep are the same mistake wearing different clothes, and the two places the codebase already applies the rule are the two places the bug does not exist.

Still open

  • Is Features a section, or a third group inside Colour by? Same act, very different interaction — and a section is also the drag unit.
  • Does the anchor default when there is exactly one row space? Settled 2026-08-13 (owner): there is no anchor and no such question. See the callout beside the specimen.
  • What is single-cell-specific here? If Coordinates and Colour by are generic over any plottable‑XY plus aligned columns, they are not single-cell at all — and that is a result, not a gap.
  • The naming. The unit becomes an extension; processor narrows to the compute inside one. Four stages, no data migration.
