CytoAnalyst · Study analysis workflow — interface design

One workspace: a biologist's guided path and a bioinformatician's full control — with room for tens of analyses to plug in

Candidate D, interface only. The workflow lives inside a study as an extensible analysis framework: every analysis (QC, clustering, integration, markers, annotation…) is a plug-in that declares a Simple surface, an Advanced surface, and a result view. A progressive-disclosure shell keeps the default path clean while every parameter stays one disclosure away. Interactive mock — switch shell direction, theme, and section below.

Recommended direction: V1 — Pipeline Timeline + Workspace, with a “Run standard analysis” recipe on-ramp for biologists and the Explorer as its own section. It reads as a legible, guided pipeline and doubles as run history / branch anchor.

V1 · Timeline + Workspace RECOMMENDED

Left run-timeline (history + branch anchor), center workspace toggling between an analysis form and its result. Reads as a guided, legible pipeline; scales because “Add analysis” opens the catalog rather than crowding the rail.

V2 · Explorer-centric ALT

The WebGL explorer is the persistent canvas; analyses live in a dock and their results overlay the scatter. Most cellxgene-like and immersive for exploration — but conveys pipeline status & “what’s next” less clearly to a first-time biologist.

V3 · Recipe + Library ALT

A prominent guided recipe card for biologists, with the full analysis library as a second tab for power users. Very friendly on-ramp; the two-surface split risks feeling like two apps and hides the run’s live state.
