# P6 — Workbench Shell + IA (Round 1, blind)

The workbench SHELL: the study-detail `Workspace` surface rebuilt as an IDE-style dock frame per
`WORKBENCH_IA.md` — center canvas host (P7) + collapsible LEFT metadata/genes dock + RIGHT
selection-inspector dock + BOTTOM results dock, collapse-to-labeled-stripe, thin top toolbar,
quiet dark data-forward chrome, fixed (not free) docking. It HOSTS the P7 viz canvas and renders
contributions from the P5 registries (host-rendered form-from-schema + result-from-result-kind +
standard result/table panels; code-panel injection only for interactive tools). Supersedes the
interface-round V2 (`components/WorkspacePanel.tsx` + `ContextPanel`/`AnalysesDock`/`ExplorerCanvas`),
which is a single constrained study-section panel inside `StudyDetailPage`'s `max-w-5xl`.

Scope: desktop + 1-box; on-system `@txresbench/kit`; render from the P5 contribution registries with a
fallback adapter over the existing `analysisRegistry` so the shell lands before P5/P7 merge.

## Items

- **ITEM-1 — Kit `Resizable` export.** The workbench needs resizable docks; the SDK ships
  `sdk/packages/kit/src/shadcn/resizable.tsx` (react-resizable-panels) + `shadcn/collapsible.tsx` but
  neither is re-exported from `kit/index.ts`. Add a thin `kit/resizable.tsx` wrapper (ResizablePanelGroup
  / ResizablePanel / ResizableHandle, kit-tokened + `data-slot`) and export it (+ `Collapsible` if the
  stripe uses it) from `index.ts`. One new kit export, no new npm dep (react-resizable-panels already
  present under shadcn). Mirror in the desktop kit copy if separate.
- **ITEM-2 — `WorkbenchLayout` store.** New Zustand store (`stores/WorkbenchLayout.store.ts`,
  `defineStore` per store-kit) holding per-dock UI state: `{ left,right,bottom: { collapsed:boolean,
  size:number }, activeTab: Record<area,string>, plotLayout:'single'|'split', resetToken }`. Actions:
  `toggleDock(area)`, `setSize(area,px)`, `setActiveTab(area,id)`, `setPlotLayout(m)`, `resetLayout()`.
  Persist per-user×study to `localStorage` (key `txr.wb.layout.<studyId>`); server-side persistence
  DEFERRED (open seam). `resetLayout()` restores IA defaults (left+bottom open, right open, canvas
  maximal).
- **ITEM-3 — `WorkbenchShell` dock frame.** New `workbench/WorkbenchShell.tsx` — the L/R/bottom/center
  IDE grid. Uses `ResizablePanelGroup` (horizontal outer: left · center-column · right; vertical inner
  on the center column: canvas · bottom). Reads `WorkbenchLayout`; each dock renders `Dock` (open) or
  `DockStripe` (collapsed). Fixed regions, resizable/collapsible splitters — NOT free float/detach
  (DEC: `WORKBENCH_IA` §5). Full-height region (`h-[calc(100dvh-<hdr>)]`, `min-h-0` chain) so the
  canvas fills the viewport, not a scrolling page. Renders `TopToolbar` above the grid.
- **ITEM-4 — `Dock` + `DockStripe` (collapse-to-labeled-stripe).** `workbench/Dock.tsx`: a dock body =
  kit `Tabs` (multiple `ViewContribution`s composed into one dock) + a header with collapse control +
  resize handle; on collapse the store swaps in `workbench/DockStripe.tsx` — a ~24px labeled edge
  button (icon + rotated label) that reopens on click (JetBrains/VS-2022 model, IA §6). One click
  reopen; panel discoverable, never a plain on/off toggle. a11y: `aria-expanded`, keyboard toggle,
  labeled stripe button.
- **ITEM-5 — `TopToolbar` (thin, universal).** `workbench/TopToolbar.tsx`: dataset/embedding switch ·
  plot-type (scatter/violin/…) · layout (single/split small-multiples) · color-by indicator · Run
  (standard recipe) · Export · Reset-layout. Built from kit `Segmented`/`Select`/`Button`/`Dropdown`.
  Plot-type + layout drive P7's canvas layout mode (P6 owns the CONTROL, P7 renders); Run/Export reuse
  the existing recipe + `ExportMenu`. Reset-layout → `WorkbenchLayout.resetLayout()`.
- **ITEM-6 — `CenterCanvasHost` (hosts P7).** `workbench/CenterCanvasHost.tsx` — the seam that mounts
  P7's view-kind grid + Coordination store as the center hero (single hero, never a tab, never split
  by default; small-multiples is a P7 layout mode toggled from the toolbar). Fallback: renders the
  existing `ExplorerCanvas` + `ColorByControl`/`ClusterLegend` overlays until P7 lands, behind a
  `hasVizFramework` flag. Empty state (kit `Empty`, "Your cells will appear here").
- **ITEM-7 — Semantic slot resolver.** `workbench/slots.ts` — maps a P5 `ViewContribution`/typed
  contribution to a dock area with SEMANTIC placement (IA §4.5.3): `field-provider→left`,
  `result-kind→bottom`, `selection-inspector→right`, `view-kind/overlay→center`; honor an explicit
  `area` on `ViewContribution`, but REJECT invalid placements (a result table can't land left).
  Groups contributions per area, orders by `order`, gates by `when`/`requires` (data-kind availability
  from the catalog) so a dock/tab appears only when applicable. Fallback adapter maps the existing
  `analysisRegistry` catalog + produced-kinds into this shape.
- **ITEM-8 — `ViewHost` (render one contribution).** `workbench/ViewHost.tsx` — dispatches a
  `ViewContribution.render` (IA §1.1): `{schema}`→SchemaForm (ITEM-9), `{table}`/result-kind→
  ResultPanelHost (ITEM-10), `{plot}`→a P7 view-kind cell, `{component}`→a built-in code panel
  (interactive tools §4.4), `{iframe}` DEFERRED. Host-owned chrome (header/collapse/resize); the
  module fills only the content slot, built from `@txresbench/kit` so contributed panels look native
  (IA §4.5.2).
- **ITEM-9 — Host-rendered form-from-schema (`SchemaForm`).** `workbench/panels/SchemaForm.tsx` — the
  ~90% declarative path (IA §4.3). Renders a JSON-schema params form over kit controls: number→
  InputNumber/slider (min/max/step), enum→Select, string→Input, boolean→Switch, array→MultiSelect.
  Tier-2: `artifact-ref` fields → an auto-populated, type-filtered picker (kit `Select` from the
  study's compatible artifacts via the data API / catalog — fallback: produced-kinds). Tier-3: named
  host widgets (`cell-set-selector`, `gene-selector`, `colormap-picker`, `threshold-on-histogram`) —
  registry of shared widgets the schema references (this round: `gene-selector` + a `cell-set-selector`
  stub wired to P8 selection; others stubbed). Tier-4 React code-form escape hatch = a `component`
  ViewContribution (built-in only). Supersedes `AnalysisForm`/`ContextPanel`; reuses their
  Simple⟷Advanced disclosure + progress/run wiring.
- **ITEM-10 — Host-rendered result-from-result-kind (`ResultPanelHost` + standard panels).**
  `workbench/panels/ResultPanelHost.tsx` — dispatches a produced result's `ResultKind` to the P5
  `resultRenderers` registry; provides the STANDARD built-in panels so two DE variants render in the
  SAME panel (IA §4.5.1): `StandardResultTable.tsx` (wide DE/marker table via kit `Table` —
  sortable/filterable/paginated/export, the full-width bottom-dock rule, IA decision 2), a stat/KPI
  card (reuse `ResultCard` KPIs), a provenance/methods view (reads §0.6 run node — fallback:
  `AnalysisResult.provenance`). Reuse `MarkerTable`.
- **ITEM-11 — Left dock content (Visualize).** Compose left dock from `field-provider` contributions:
  Metadata (obs columns, click→color) + Genes (search + list, click→color) tabs. This round: a
  built-in `MetadataFields` + `GeneSearch` field-provider pair reading the data API (fallback: mock
  `colorBy` in `AnalysisWorkspace`). Click sets shared color-by / selection — wired to P7 Coordination
  + P8 selection. Supersedes ad-hoc `ColorByControl`.
- **ITEM-12 — Right dock content (Selection inspector).** `workbench/panels/SelectionInspector.tsx` —
  persistent right dock: N selected · composition/stats · Assign annotation (write-back) · top-DE
  genes (IA decision 4). Thin code over P8 `api.selection` (`useCurrent`) + `selectionActions`
  contributions; assign → `data.writeAnnotation` (P1) → new left-rail metadata (closes the
  lasso→annotate loop). Fallback: a static inspector reading no selection until P8 lands. First dock to
  hide (IA).
- **ITEM-13 — Bottom dock content (Analysis + data).** Compose bottom dock tabs from analyses +
  result-kinds: Differential Expression · Markers · Clustering · Annotation · Log/provenance; each =
  config (SchemaForm) + full-width result (ResultPanelHost). Reuse `AnalysesDock`'s run-order status
  chips as a bottom-dock "Analyses" tab / run rail; reuse `AnalysisCatalog` as "Add analysis".
- **ITEM-14 — Study-shell full-bleed integration.** The workbench needs full width + viewport height,
  but `StudyDetailPage` wraps panels in `max-w-5xl p-4 sm:p-6`. Add an optional `fullBleed?: boolean`
  to `StudyDetailPanelContribution` (`study/core/extensions/types.ts`); `StudyDetailPanelSlot` /
  `StudyDetailPage` drop the max-width + padding (and let the panel own its height) for a full-bleed
  section. Update `analysis/study-extension/extension.tsx`: `workspace` panel → `WorkbenchShell`,
  `fullBleed: true`. Minimal, principled study-core edit (one flag).
- **ITEM-15 — Quiet dark, data-forward chrome.** Apply IA decision 8: near-black canvas, muted
  borders, chrome nearly invisible so data is the only color. Decide the canvas region is force-dark
  (a `data-workbench-canvas` dark scope) regardless of app theme minimum; docks theme-aware but
  low-chroma. Reuse existing tokens (`bg-card`, `border-border`, `muted`); add a small workbench dark
  surface token set if needed (coordinate with `@txresbench/kit` DESIGN_DIRECTION — "research workbench" is
  its stated subject). Directly resolves FB-1 (plain/templated) + FB-2 (restrained dark chrome).
- **ITEM-16 — Mobile/desktop responsive.** Desktop = resizable docks + stripes. Mobile/narrow =
  docks collapse to kit `Sheet`s (reuse the V2 mobile-sheet pattern); center canvas stays the hero.
  `useIsMobile`.
- **ITEM-17 — Gallery + testIds.** Register the workbench shell in the analysis module gallery
  (`analysis/gallery.tsx`) across states (empty / running / results / collapsed docks) × themes for
  the `gate:ui` runtime-health + visual pass; stable `data-testid`s on shell/docks/stripes/toolbar
  (`workbench-shell`, `workbench-dock-<area>`, `workbench-stripe-<area>`, `workbench-toolbar`,
  `workbench-canvas-host`).

## Decisions

- **DEC-P6-1 Full-bleed via a panel flag, not a breakout hack.** Add `fullBleed?: boolean` to
  `StudyDetailPanelContribution`; the shell drops `max-w-5xl`/padding + yields height for that section.
  Cleaner + reusable vs a negative-margin `-mx` breakout inside `max-w-5xl`.
- **DEC-P6-2 Resizable = react-resizable-panels via a kit export** (already a shadcn dep) — no new npm
  dependency; docks are fixed regions + resizable/collapsible splitters (IA §5, "fixed not free").
- **DEC-P6-3 Collapse-to-labeled-stripe** (custom ~24px edge button), NOT shadcn `Collapsible`
  show/hide and NOT a plain ⌘B toggle — the store owns sizes; a collapsed dock is a discoverable
  labeled stripe (IA §6).
- **DEC-P6-4 Center = one hero, host-seamed to P7.** Never a tab, never split by default; plot-type +
  small-multiples are a P7 canvas LAYOUT MODE driven by the P6 toolbar control (IA decision 1/7).
- **DEC-P6-5 Panels host-rendered by default; injection only for interactive tools.** ~90% of docks are
  host-standard (SchemaForm + ResultPanelHost); a `component` ViewContribution is the only injection,
  built from `@txresbench/kit` into a semantic slot the host composes (IA §4.5). `iframe` code-views
  DEFERRED.
- **DEC-P6-6 Semantic placement enforced.** Area derived from contribution type (field→left,
  result→bottom, inspector→right, view→center), honoring explicit `area` but rejecting invalid drops —
  keeps the workbench from becoming a junk drawer (IA §4.5.3).
- **DEC-P6-7 Layout persistence = localStorage per study, this round.** Server-side per-user layout is
  an open seam (DEFERRED, 1-box scope). `Reset layout` always available.
- **DEC-P6-8 Quiet dark, data-forward chrome.** Force-dark canvas region minimum; low-chroma dock
  chrome. Resolves FB-1/FB-2; supersedes the earlier glowy-glass direction.
- **DEC-P6-9 P5/P7/P8-fallback adapters ship in P6** so the shell lands + is demoable before those
  parts merge (adapter over `analysisRegistry` + `AnalysisWorkspace` mock; ExplorerCanvas center;
  static inspector).

## Risks / unknowns

- **P5 registries unbuilt (blind parallel round).** The exact `ViewContribution.render` union +
  `WorkbenchAPI` shape may shift; the adapter isolates P6 but a contract change ripples into ViewHost/
  SchemaForm/slots. Mitigate: code to §1/§2 verbatim + a single adapter boundary.
- **P7 center engine unmerged + deck.gl-only.** CenterCanvasHost seam + ExplorerCanvas fallback; the
  small-multiples/linked-brushing (FB-2) depends on P7's grid + Coordination store landing.
- **Full-height inside a scrolling page.** StudyDetailPage is a scrolling `max-w-5xl` column; the
  `fullBleed` flag + a `h-[calc(100dvh-…)]`/`min-h-0` chain must be gotten exactly right or the docks
  won't fill/scroll correctly (nested-scroller regressions are e2e-only-caught — see memory
  `project_chats_page_virtualization`).
- **Collapse-to-stripe a11y + keyboard resize** — react-resizable-panels handle focus + the stripe
  button need explicit `aria-expanded`/roles; must pass axe in the runtime-health gate.
- **Dark-chrome vs app theme** — forcing a dark canvas region while docks follow theme can create a
  seam/contrast mismatch; needs a token decision with `@txresbench/kit`.
- **Layout key stability** — dock ids change as contributions register; persisted sizes must key by a
  stable `area`, not per-tab id, or a reset is forced on contribution churn.
- **Desktop (Tauri) window** — full-height + resizable panels under the desktop shell chrome; verify
  the desktop-embedded path (`CORE_MODULE_BLOCKLIST`/config parity, memory `project_desktop_embeds_server`).
- **Superseding the V2 without breaking its 14/14 e2e** — the interface-round e2e targets
  `analysis-workspace*` testIds; either migrate those specs or keep compatibility testIds during the
  swap.
