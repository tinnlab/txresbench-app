# P6 — Workbench Shell (r2)

The frontend shell that renders the researched IA (`WORKBENCH_IA.md`) from the P5 contribution
registries and hosts the P7 canvas. Owns the docks (L/R/bottom/center), collapse-to-stripe, the thin
top toolbar, semantic slot placement, and the two HOST renderers (form-from-JSON-schema,
result-from-kind). **Desktop + single-box server only** — no free/float/detach docking (fixed
collapsible slots per IA decision 5), no multi-topology concerns.

Boundary: P6 renders FROM the P5 registries + `WorkbenchAPI`; it does NOT define them. It hosts the
P7 viz engine in the center; it does NOT build view-kinds. It provides dock frames + selection wiring
seams; the selection/interaction semantics are P8, the concrete fieldProviders/analyses/view-kinds are
P11. The shell mounts as the study `workspace` detail-panel (P10 substrate), replacing the superseded
V2 `WorkspacePanel`.

## Items

- **ITEM-1**: **Dock scaffold layout primitive.** A 4-region shell frame — left / center / right edge
  docks in a horizontal `ResizablePanelGroup`, with the bottom dock as a vertical split wrapping the
  center column (center-canvas + bottom-results stack, so the bottom dock spans center width only, per
  IA: "wide tables go full width below the canvas, never beside"). Resizable splitters with min/max
  sizes; center is the flex hero that never collapses. Export `Resizable*` from `@ziee/kit` (the
  `shadcn/resizable.tsx` react-resizable-panels wrapper exists but is not exported today).

- **ITEM-2**: **Collapse-to-labeled-stripe.** Each edge dock (L/R/bottom) collapses not to nothing but
  to a ~24px labeled stripe on its edge (vertical text L/R, horizontal bottom) with the dock's title +
  icon; one click re-expands to its last size. JetBrains/Visual-Studio model per IA decision 6 — canvas
  maximal by default, every dock discoverable. Center never gets a stripe.

- **ITEM-3**: **Layout state store + persistence + Reset layout.** A `WorkbenchLayout` store holding per
  dock `{ collapsed, size }` + active-tab-per-dock + the toolbar's plot-type/layout-mode/color-by
  indicator selections. Persist per-study (localStorage keyed by studyId, mirroring split-chat's
  `splitWorkspace.persist`). A `workbench.resetLayout` command restores IA defaults. Reads reactively
  in the shell; `ensureStudy(id)` resets on study switch.

- **ITEM-4**: **Thin top toolbar frame.** The host-owned toolbar: built-in controls (dataset/embedding
  switch · plot-type selector · layout mode single/split · color-by indicator · Run · Export ·
  Reset-layout) PLUS a `commands`-registry injection region so a contribution's `CommandContribution`
  (toolbar-targeted) renders as a button. Quiet, dense, single row; overflow menu on narrow width.

- **ITEM-5**: **Semantic slot placement engine.** The core of P6: read the P5 `views` registry, route
  each `ViewContribution` to its declared `area` (left/right/bottom), compose multiple contributions in
  one dock as tabs ordered by `order`, and gate visibility by `when` / `requires` (against the study's
  produced data-kinds / catalog). Enforce **semantic placement** (a result-kind can't land left; a
  field-provider can't land bottom) per §4.5.3 — the placement is typed, not "anywhere." A pure
  `placeViews(registry, area, ctx)` selector so gating is unit-testable and gallery-observable.

- **ITEM-6**: **Left dock host — "Visualize."** Renders the `fieldProviders` registry as the
  metadata-fields + gene-search list; a single click on a field/gene calls `api.selection`/color-by to
  recolor the canvas (click-to-color, NOT drag — cellxgene consensus). Hosts any left-targeted `views`
  (ITEM-5). Gene search = filterable list. The provider *rows* come from P5/P11; P6 owns the frame,
  search chrome, and the click→color-by dispatch seam.

- **ITEM-7**: **Right dock host — Selection inspector.** The persistent selection flyout frame: N
  selected · composition/stats region · an `assign-annotation` write-back action · top-DE region · and
  the `selectionActions` registry rendered as the offered actions on the current selection. Hosts
  right-targeted `views`. Stable (not inline-expand) per IA decision 4. The stats/DE *content* is P11;
  P6 owns the frame + the selection-driven refresh seam (subscribes to `api.selection.onChange`).

- **ITEM-8**: **Bottom dock host — Analysis + data.** Tabbed, resizable, full-width results dock:
  bottom-targeted `views` become tabs (Differential Expression · Markers · Clustering · Annotation ·
  Log/provenance). Each analysis tab = the host-rendered config form (ITEM-9) + the host-rendered result
  panel (ITEM-10). This is where wide tables live (the full-width argument).

- **ITEM-9**: **HOST form-from-JSON-schema renderer.** Render an `AnalysisContribution.params` JSON-
  schema into a form with zero per-analysis UI code (§4.3), four tiers: **Tier 1** scalar schema →
  controls (number→slider/input min/max/step, enum→Select, string→Input, boolean→Switch, array); **Tier
  2** `artifact-ref` fields → auto-populated, type-filtered pickers (Select of the study's compatible
  artifacts via `api.data.catalog()` + `accepts` match) — the "clustering needs an embedding" case;
  **Tier 3** a host-widget slot (`widget: cell-set-selector | gene-selector | colormap-picker | …`) that
  dispatches to a registry of shared rich widgets; **Tier 4** a code-form escape (a contribution-supplied
  `ParamsForm` React component). Progressive disclosure (Simple/Advanced) + conditional `when`/`if-then`
  field visibility. Replaces V2's per-plugin `SimpleForm`/`AdvancedForm`.

- **ITEM-10**: **HOST result-from-kind renderer.** Dispatch a produced result's `ResultKind` through the
  P5 `resultRenderers` registry to a standard host panel (DE-table, stat-card, provenance view, generic
  table) so two DE variants render in the *same* panel (§4.5.1). Fallback generic renderer for an
  unknown kind. Replaces V2's per-plugin `ResultView`. Wire the run lifecycle (idle → running w/
  progress → done/error) from `api.compute` job handles (P5), superseding the V2 mock `run()`.

- **ITEM-11**: **Center dock host — the canvas hero.** Mount the P7 (`feat/visualization`) grid engine
  as the permanent center canvas; enforce canvas-hero discipline (never reflows/tabs the canvas —
  recolor updates in place, IA decision 1). Provide a floating-legend overlay slot + the lasso/brush
  inline affordance passthrough (the canvas owns pick/lasso; P6 only frames it). Layout-mode
  single/linked-small-multiples toggles the engine's grid (its Coordination store = linked brushing).
  This is the integration seam to P7.

- **ITEM-12**: **Study-substrate mount + responsive fallback + chrome.** Register the shell as the study
  `detail_panels` `workspace` section (zero-prop, reads `Stores.StudyDetail`) via
  `studyExtensionRegistry`, replacing the V2 `WorkspacePanel`/`ContextPanel`/`AnalysesDock`. On mobile
  (`useIsMobile`) edge docks degrade to `Sheet`s (V2 precedent). Quiet-dark, data-forward chrome tokens
  (near-black, muted borders, chrome invisible so the data is the only color — IA decision 8); no raw
  colors (design-system tokens only). Gallery story + completeness gate for every dock × state × theme.

## Dependencies
- **HARD BLOCKER — P5 contribution-api**: P6 renders entirely from the P5 registries + `WorkbenchAPI`
  (`views`, `fieldProviders`, `resultRenderers`, `selectionActions`, `commands`; `data`, `selection`,
  `compute`). Nothing in P6 renders real content without it. Build against a stub `WorkbenchAPI` if P5
  lags, but the registry types must land first.
- **P7 visualization**: ITEM-11 mounts its grid engine as the center canvas. P6 can scaffold with a
  placeholder canvas and swap when P7 lands.
- **P10 study-substrate**: the `workspace` detail-panel mount + `Stores.StudyDetail` (already present in
  the tree).
- **P8 interaction-dsl** (soft): P6 exposes the selection-driven refresh seams; P8 supplies the
  lasso→inspector→results wiring semantics. P6 frames; P8 wires.
- **P11 three-modules** (soft, downstream): consumes P6's slots/forms/renderers; not a build dep.

## Sequencing
1. ITEM-1 + kit `Resizable` export → the static 4-region frame (placeholder panels).
2. ITEM-3 layout store → ITEM-2 collapse-to-stripe (needs the store).
3. ITEM-5 placement engine (pure, testable) — the spine every dock host consumes.
4. ITEM-4 toolbar (thin, mostly independent; color-by/plot-type read the store).
5. ITEM-9 SchemaForm + ITEM-10 ResultPanel (the two host renderers; parallelizable, both need P5 types).
6. ITEM-6/7/8 dock hosts (consume ITEM-5 + ITEM-9/10).
7. ITEM-11 center canvas (swap placeholder for P7).
8. ITEM-12 mount + responsive + chrome + gallery gate (last — needs all docks to render a real story).

## Decisions
- **Fixed collapsible slots, NOT free docking** (IA decision 5) — no pin/float/detach; predictability >
  power for episodic-use scientists. Ship "Reset layout."
- **Collapse-to-stripe (24px labeled), not binary on/off** (IA decision 6).
- **Center never collapses / never tabs / never reflows on recolor** — canvas-hero discipline
  (IA decision 1).
- **Bottom dock spans center-column width only** (vertical split *inside* the center column), so the
  L/R docks stay full height and the wide DE tables get canvas width — matches the IA ASCII.
- **Placement is semantic + typed** (§4.5.3): route by `ViewContribution.area` + kind, reject
  mis-targeted contributions; the shell composes tabs/order/collapse, the module owns a tab not a dock.
- **Host-rendered by default, inject only for interactive tools** (§4.5.1): ~90% of panels are the
  ITEM-9 form + ITEM-10 result renderer; a code panel is the escape hatch, kit-built.
- **Form tiers 1–4 exactly per §4.3**; artifact-ref pickers auto-populate from the catalog (Tier 2 is
  the headline). Do NOT let each analysis hand-code a picker.
- **Persist layout per-study in localStorage** (client-only; no server table for shell layout in scope).
- **Quiet-dark, data-forward chrome** (IA decision 8); design-system tokens only, no raw colors.

## Risks
- **P5 registry shape churn** — P6 is a pure consumer; an unstable `WorkbenchAPI`/`ViewContribution`
  contract ripples through every dock host. Mitigate: lock the registry types with P5 first; build P6
  against a typed stub. (Highest risk.)
- **SchemaForm scope creep (ITEM-9)** — RJSF-style host rendering + artifact-ref pickers + host-widget
  registry + code escape is genuinely large; the legacy param inventory (71 Select / 23 InputNumber / …)
  bounds Tier 1, but Tier 2/3 are new. Keep Tier 4 (code-form) as the pressure valve; don't gold-plate
  Tier 1 conditionals.
- **P7 canvas integration seam** — the viz engine is standalone; the mount contract (data props,
  selection/color-by callbacks, resize behavior) is undefined until adopted. Placeholder-first, swap late.
- **Resizable + collapse-to-stripe interaction** — react-resizable-panels min-size vs a 24px stripe can
  fight; may need the stripe rendered *outside* the panel group (an overlay rail) rather than as a
  collapsed panel. Prototype ITEM-2 early.
- **Mobile fallback fidelity** — 3 edge docks → sheets can bury the selection loop; verify the
  lasso→inspect→results flow survives on narrow width (or accept desktop-first per scope).
- **Superseding V2 without regressing the gallery gate** — the V2 `analysis/components/*` gallery
  stories must be replaced, not left dangling (source-walking completeness gate).

## Effort
Large — the flagship frontend of the platform. Rough split: dock scaffold + collapse + layout store
(ITEM-1/2/3) ≈ medium; placement engine + 4 dock hosts (ITEM-5/6/7/8) ≈ medium-large; **SchemaForm +
ResultPanel (ITEM-9/10) ≈ the largest single chunk**; toolbar + center mount + study mount + chrome +
gallery (ITEM-4/11/12) ≈ medium. Total ≈ the biggest of the P-parts; sequence behind P5, parallelize
the two host renderers against the dock hosts.
