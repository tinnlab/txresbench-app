# P11 — The three modules as no-Rust extensions (data-io · embedding · clustering)

The **vertical slice** that proves the microkernel (§8.5): three self-contained extensions —
`extensions/{data-io,embedding,clustering}/` — each a **manifest + sandboxed Python (scanpy) compute +
declarative form + frontend contributions**, ZERO Rust. They compose purely through the typed-artifact graph
(`accepts`/`produces`), never importing one another. This part builds NO platform machinery; it **consumes**
P1–P10 and is the acceptance test that "add a feature = drop a folder, kernel unchanged."

Grounding: turns the interface-round seed plugins (`ui/src/modules/analysis/analyses/{qc-filter,normalize-lognorm,pca,umap,leiden}/plugin.tsx`)
into real extensions, ports the legacy compute (`sc-website-scripts/{data-process,embedding-create,clustering-create,save-sample}.R`
+ their `job-templates/*.ts` onCompleted hooks) from R/Seurat → Python/scanpy, and reuses the legacy forms'
param logic (`imports/ui/pages/Analysis/{Clustering,Embedding}/New*Form.tsx`) as declarative schemas.

## Items

### Module 1 — `data-io` (upload → process(QC+normalize) → save)
- **P11-DIO-1** — `extensions/data-io/extension.yaml`: `id: txr.data-io`, `apiVersion: "^1.0"`,
  `activation:[onView:samples, onAnalysis:data.process]`. Contributes: `analyses:[data.process, save.sample]`,
  `views:[samples(left), qc-review(bottom)]`, `settings:[qc-defaults]`. (§8.5 module-1 manifest verbatim as the
  template.)
- **P11-DIO-2** — `analyses.data.process`: `accepts:[{type: file/upload}]` (a host file-store handle, the ONLY
  root-input analysis) → `produces:[{id:expression,type:single-cell/expression},{id:qc_metrics,type:metadata-column,multiple},{id:qc,type:qc-report}]`.
  Multi-output run (DATA_MODEL "one run → N artifacts"). `run:{kind:sandbox,runtime:python,entry:compute/process.py}`,
  `schedule:{class:interactive|batch, resources:{cpu:2,mem:8Gi}}`.
- **P11-DIO-3** — `schema/process.params.json` (JSON-schema, Tier-1 + Tier-2 fields, ported from legacy
  `data-process.R` params + `NewEmbeddingForm` preprocessing block): `fileType(enum: anndata/10x-h5/10x-mtx)`,
  `assay`, `cellIdColumn`, `featureIdColumn`, `hasMultipleSamples` + `sampleIdIn/Delimiter/Position/Column`
  (sample-split), QC block `{maxMitoPct, minGenes, minCounts, strategy(adaptive|fixed), nmads}` (from seed
  `qc-filter`), normalize block `{method(shifted-log|pearson), targetSum, nHVG}` (from seed `normalize-lognorm`),
  `mitochondrialGenesRegex` default `^MT-|^mt-`.
- **P11-DIO-4** — `compute/process.py` (scanpy): read `/inputs/matrix.*` (h5ad via `anndata.read_h5ad`, or 10x
  via `sc.read_10x_h5`/`sc.read_10x_mtx`) + `/inputs/params.json` → compute per-cell QC (`sc.pp.calculate_qc_metrics`:
  n_counts, n_genes, pct_counts_mt, pct_counts_ribo) → threshold/adaptive-MAD filter → optional sample split
  (barcode-delimiter or obs column) → `sc.pp.normalize_total`+`sc.pp.log1p` (or `pearson_residuals`) → HVG
  (`sc.pp.highly_variable_genes`, seurat_v3) → write `/outputs/expression.zarr` (AnnData-Zarr per DATA_MODEL
  storage §), `/outputs/qc_*.parquet` obs columns, `/outputs/qc-report.html` (per-sample retained/removed +
  the "sample lost 28%" guardrail as real numbers), `/outputs/manifest.json` naming produced ids/types.
  Port the read paths from legacy `utils/h5Parse.R` semantics (CSC reconstruct, assay filtering, categorical
  decode) — scanpy handles most natively.
- **P11-DIO-5** — `analyses.save.sample`: `accepts:[{type:single-cell/expression}]` → `produces:[{id:sample,type:single-cell/sample}]`,
  `run:compute/save.py`. Ports `save-sample.R`/`sample-save.ts`: apply per-sample manual thresholds, persist named
  samples + their nCells + carried embeddings. (May collapse into `data.process` if the split is done there — see
  Decision D3.)
- **P11-DIO-6** — `schema/qc.settings.json` (deployment `settings` provisioner, P5-A): default QC thresholds an
  admin sets; host renders the admin card + GET/PUT, no code (§8.5 module-1 `settings: qc-defaults`).
- **P11-DIO-7** — `ui/UploadPanel.tsx` (code `view`, left dock): drag-drop to the host **file store** (`api.files.upload`),
  list uploads, "Process" launches `data.process`. Built on `@txresbench/kit` + `@txresbench/workbench-api`. Reuses the
  interface-round `SamplesPanel.tsx` shape.
- **P11-DIO-8** — `ui/QcReviewPanel.tsx` (code `view`, bottom, `when:"has:qc-report"`): renders the `qc-report`
  artifact (per-sample violin/threshold review, live cell-count preview) → adjust thresholds → re-run `save.sample`.
  This is the ONE mildly-interactive surface (§4.4 "code panel"); reads `api.data` for the qc-report + writes via
  a `save.sample` re-run. Reuses seed `qc-filter` advisory/KPI copy.

### Module 2 — `embedding` (pca / umap → embedding)
- **P11-EMB-1** — `extensions/embedding/extension.yaml`: `id: txr.embedding`, `analyses:[embedding.pca, embedding.umap]`,
  `fieldProviders:[embeddings]`, `activation:[onAnalysis:embedding.umap, onAnalysis:embedding.pca]`.
- **P11-EMB-2** — `analyses.embedding.pca`: `accepts:[{type:single-cell/expression}]` → `produces:[{id:reduced,type:embedding,subtype:pca}]`.
  `schema/pca.params.json` from seed `pca` plugin: `{nComps(10–100,def 30), whiten, seed}`. `compute/pca.py`:
  `sc.pp.scale`(opt) → `sc.tl.pca(n_comps)` → write `/outputs/pca.zarr` (obsm/X_pca) + manifest.
- **P11-EMB-3** — `analyses.embedding.umap`: `accepts:[{type:embedding,subtype:pca}]` (OR expression, computing a
  neighbor graph first) → `produces:[{id:embedding,type:embedding,subtype:umap-2d}]`. `schema/umap.params.json`
  from seed `umap`: `{minDist(0.1–1,def 0.5), neighbors(5–100,def 15), metric(euclidean|cosine), seed}`.
  `compute/umap.py`: `sc.pp.neighbors` → `sc.tl.umap` → write obsm/X_umap Zarr + manifest.
- **P11-EMB-4** — `ui/EmbeddingFields.tsx`: registers a **fieldProvider** so the left rail offers "color/select by"
  the produced embeddings; the built-in **scatter view-kind** (P7) renders the 2D embedding. No custom canvas.
  Reuses interface-round `ColorByControl.tsx`/`ClusterLegend.tsx` patterns.
- **P11-EMB-5** — (port note) legacy `embedding-create.R` folds normalize+HVG+integration(Harmony)+PCA+UMAP into
  ONE job; the platform DECOMPOSES it (normalize→data-io, pca+umap→embedding, integration→a separate `harmony`
  extension already seeded). Carry only PCA+UMAP scanpy logic here; Harmony/integration is out of P11 scope
  (seed `harmony/plugin.tsx` exists as the 4th module template).

### Module 3 — `clustering` (leiden / louvain → clustering)
- **P11-CLU-1** — `extensions/clustering/extension.yaml`: `id: txr.clustering`, `analyses:[clustering.leiden, clustering.louvain]`,
  `fieldProviders:[clusterings]`, `selectionActions:[{id:subcluster, when:"has-selection", command:clustering.leiden}]`.
- **P11-CLU-2** — `analyses.clustering.leiden` — **THE artifact-ref-picker case (§4.3 Tier-2)**. `schema/leiden.params.json`:
  `params:[{id:embedding, type:artifact-ref, accepts:embedding, multiple:true, required:true}, {id:resolution,
  number,0.1–2,def 0.6}, {id:algorithm, enum:[leiden,louvain]}, {id:neighbors,int,def 15}, {id:nPcs,int,def 30},
  {id:seed}]`. The `embedding` field renders as a **host-populated Select of the study's `embedding` artifacts**
  (P6 form renderer + P2 catalog query) — the extension writes NO select code (replaces legacy `useEmbeddings()`
  hand-wiring in `NewClusteringForm.tsx`). `accepts` doubles as availability gate (clustering UI hidden until an
  embedding exists).
- **P11-CLU-3** — `compute/leiden.py` (scanpy): read `/inputs/embedding.zarr` (obsm) + params → `sc.pp.neighbors` →
  `sc.tl.leiden`/`sc.tl.louvain(resolution)` → write `/outputs/clustering.parquet` (obs categorical codes+categories,
  a `metadata-column`-shaped `clustering` artifact) + manifest. `produces:[{id:clustering,type:clustering}]`.
- **P11-CLU-4** — `analyses.clustering.louvain`: same compute entry, `algorithm=louvain` default (one script, param
  switch — mirrors seed `leiden` plugin's algorithm advanced field).
- **P11-CLU-5** — dynamic/dependent field: legacy `nCluster_{embeddingId}` per-embedding + kmeans-only visibility →
  declarative `repeat-per` (a sub-form per selected embedding artifact-ref) + `when:"method==kmeans"` conditional
  (§4.3 "dependent/dynamic fields"). Scope P11 to leiden/louvain (drop kmeans) unless P6 supports `repeat-per`
  (Decision D5).
- **P11-CLU-6** — `ui/ClusterFields.tsx`: fieldProvider registering "color by clustering" (categorical legend on the
  shared scatter); the `subcluster` selectionAction re-runs leiden on the lassoed `api.selection` (P8) → new
  `clustering` artifact. Thin code over shared primitives (§4.4).

## Sequencing
1. **P11-X-1** (datatype mapping) — pick the 5 seed datatypes; needed before any manifest is written.
2. **data-io first** (P11-DIO-*) — it produces `expression`, the root the other two require; also exercises the
   hardest paths (file upload, multi-output ingest, settings provisioner). Ship `data.process` before `save.sample`.
3. **embedding** (P11-EMB-*) — `expression`→`embedding`; unlocks the scatter canvas + fieldProvider.
4. **clustering** (P11-CLU-*) — `embedding`→`clustering`; proves the artifact-ref picker (the headline §4.3 case)
   and the subcluster selectionAction (last, needs P8).
5. **P11-X-3/X-4** — discovery wiring + the end-to-end compose E2E, after all three exist.
Within each module: manifest+schema (declarative, testable against the P5 validator) → compute.py (testable
standalone against a fixture h5ad) → ui/*.tsx (needs P6/P7) → wire into discovery.

## Decisions
- **D1** — Compute language: **Python/scanpy**, NOT the legacy R/Seurat. §8.5 uses `process.py`; the seed plugins
  say scanpy; the platform rootfs (P3) standardizes on Python. Port R logic → scanpy equivalents.
- **D2** — Served storage: **AnnData-Zarr** for expression/embedding, **Parquet** for obs columns/clustering/qc
  tables (DATA_MODEL storage table). Compute writes Zarr directly (scanpy/anndata native) so no HDF5→Zarr convert
  step; qc-report as `report/html`.
- **D3** — `save.sample` as a SEPARATE analysis vs folded into `data.process`. Lean: keep separate (§8.5 lists
  `save.sample`; the legacy split has it re-apply thresholds interactively). But if sample-split happens in
  `data.process`, `save.sample` may reduce to a persist/rename — revisit against P6's QC-review interaction.
- **D4** — Seed decomposition: the 5 seed analyses map to 3 modules as data-io={qc,normalize}, embedding={pca,umap},
  clustering={leiden}. `harmony`/`markers`/`annotation` seeds are OUT of P11 (future modules 4+). Record the
  qc/normalized/reduced Kind → expression/embedding subtype reconciliation.
- **D5** — kmeans + per-embedding `nCluster` dynamic field: DROP from P11 (leiden/louvain only) unless P6 ships
  `repeat-per`. Keeps the artifact-ref picker the clean demonstrator without the dynamic-field complexity.
- **D6** — QC thresholds: default **adaptive (MAD)** per the seed `qc-filter`, even though legacy used fixed
  user min/max. Expose both (`strategy` enum). Admin default via the `qc-defaults` settings row.
- **D7** — Multi-output: `data.process` emits N artifacts from ONE run (expression + qc columns + qc-report),
  per DATA_MODEL "produce-atomically / consume-individually." Requires P1 ingest to handle the fan-out manifest.

## Risks / unknowns
- **R1 (critical-path)** — P11 is 100% blocked on P1+P2+P3 (foundation). If those slip, P11 can only build
  manifests+schemas+compute.py against fixtures, not run end-to-end. Mitigate: build/test compute.py standalone
  (scanpy on a tiny h5ad) independent of the host.
- **R2** — The **artifact-ref picker** (P11-CLU-2) is the platform's headline claim but lives in P6. If P6's form
  renderer doesn't yet support `type:artifact-ref` → catalog-query binding, clustering's key demo can't render.
  Tight P6↔P11 contract needed early.
- **R3** — Scanpy port fidelity: legacy R read paths handle CITE-seq assay filtering, legacy categorical encoding,
  10x v2/v3 layouts, COO vs CSC (digest §2–3). scanpy covers most but edge formats may need manual handling in
  `process.py`. Scope P11 to h5ad + 10x-h5 happy path; flag exotic formats.
- **R4** — Rootfs must ship scanpy + anndata + zarr + leidenalg + igraph + umap-learn (P3). Confirm the scientific
  rootfs includes these; a stub/missing dep silently disables all three modules.
- **R5** — QC-review interactivity (P11-DIO-8) blurs the declarative/interactive line (§4.4). If it needs a real
  stateful loop it's a code panel dep on P6 kit + P1 data API; keep it read-render + re-run, not a bespoke canvas.
- **R6** — `metadata-column` alignment: qc columns + clustering codes must align to the study's canonical
  `system_cell_id` axis (DATA_MODEL). Compute must emit cell-id-keyed columns; the host aligns on ingest — verify
  the contract with P1.
- **R7** — No P11 Rust is the whole thesis; if any module reaches for a kernel change, that's a platform gap
  (P5/P6) to fix in-kernel, not a per-module Rust file. Treat any such need as a defect against the foundation.

## Effort estimate
- **data-io**: L (upload UI + multi-output compute + QC-review panel + settings + the hardest read paths) — ~40%.
- **embedding**: S–M (two thin scanpy scripts + fieldProvider; reuses scatter) — ~20%.
- **clustering**: M (artifact-ref picker demo + subcluster selectionAction + one script) — ~25%.
- **cross-module** (datatype mapping, discovery wiring, compose E2E): M — ~15%.
- Total P11 ≈ **3–4 focused sessions** ONCE P1/P2/P3/P5/P6/P7 exist; near-zero of it is novel infra (all reuse +
  port). The value is proving the seams, not writing lines. Standalone compute.py can proceed earlier against
  fixtures to de-risk R3/R4.
