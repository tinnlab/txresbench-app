# P2 — Datatype System (build plan, round 3)

Blind round. Grounded in the actual code (main baseline `63520fb`) + the design corpus (`DATA_MODEL.md`,
`PLATFORM_ARCHITECTURE.md` §5/§5.5/§4.2, `BUILD_PLAN.md` Phase 0/1). Does **not** consult r1/r2/DIFF.

**Scope (from PLANNING_INDEX):** open datatype registry + subtyping lattice + artifact *typing* + storage
layouts (dense/sparse/columnar/1-d) + viewers-per-datatype dispatch. Desktop + single-box; keep seams open,
build only the local arm.

## 0. Grounding — what actually exists today (main)

- App = the worktree; backend `src-app/server/src/modules/`, frontend `src-app/ui/src/`. SDK vendored at
  `sdk/crates/*` (`@ziee/*`) + `sdk/packages/*`. **No `@cyto/*` packages; the UI is one Vite app, not internal
  npm packages.**
- Backend `modules/dataset/` = a ziee `AppModule` (`#[distributed_slice(MODULE_ENTRIES)]`, order 20). Its
  migrations create a **placeholder** `datasets` table (`id, name, n_cells, n_genes, status, file_id→files`).
  **No `artifacts`/`analysis_results`/catalog/`file_chunks` table exists in any worktree.** Only blob store =
  SDK `ziee-file` (`sdk/crates/ziee-file/`: opaque multi-derivative bytes keyed by `file_id`, `ingest.rs` +
  `FilesystemStorage`).
- Frontend closed vocabularies to generalize: `modules/analysis/types.ts` `Kind = 'qc'|'normalized'|…` +
  `modules/analysis/registry.ts` `AnalysisRegistry` singleton (`register/all/byCategory/availability/
  standardRecipe`) — the exact registry pattern P2 mirrors; and viz `viz-core/data/wire.ts`
  `ColumnKind`/`DataSource`/`DatasetCatalog` typed-binary wire contract.
- viz view dispatch = **closed exhaustive `switch(cell.kind)`** over `CellKind` in
  `viz-core/grid/CellView.tsx` (+ a twin in `adapter/PopoutWindow.tsx`); `showcase/registry.ts` is a story
  catalog, **not** a view-kind plugin registry.
- Distributed-slice self-registration precedent: `dataset/study_extension/extension.rs` `STUDY_EXTENSIONS`.
- Migrations are date-timestamped `YYYYMMDDNNNN_<module>_<name>.sql`, co-located per module, globbed into
  `migrations-merged/`. Highest today = `202607190005`. Any new file slots at `20260720xxxx`.

**Net: P2 is design-complete-on-paper, zero-implemented.** No datatype code, no artifacts table.

## 1. The two ownership decisions this plan settles (the caller's questions)

### DEC-1 — The `artifacts`/catalog table is owned by **P1 (data-foundation)**, NOT P2.
P2 owns **no table.** Rationale, straight from the corpus:
- `DATA_MODEL`: "the **catalog** indexes `(datatype, storage-ref, shape, provenance)` uniformly" +
  "Catalog / relational metadata — **Postgres (the host-owned index)**."
- `PLATFORM_ARCHITECTURE` §5.5-B: "The catalog — Postgres, **host-owned**… **Extensions don't own catalog
  tables**."
- `BUILD_PLAN` Phase 0a = "**Working store + catalog**" = P1's exact PLANNING_INDEX scope. The catalog is the
  Phase-0 **domain-neutral foundation** that P4 (provenance run/edge FKs), P7 (viz reads rows), and the whole
  platform depend on — it cannot belong to the type-semantics layer.

The design's thesis is that the host provides **domain-neutral capabilities that don't know what single-cell
is** (DATA_MODEL Tier-1/2). The artifacts **row+blob store is exactly such a host capability ⇒ P1.** The
**datatype registry is the semantic layer ⇒ P2.** Clean split:

| | P1 (owns) | P2 (owns) |
|---|---|---|
| `artifacts` row store | ✅ `id, study_id, datatype TEXT, layout TEXT, storage_ref, content_hash, shape JSONB, source bool, produced_by_run_id, covered_axes, created_at` | — |
| blob store + authed byte-Range endpoint | ✅ (`ziee-file` generalized) | — |
| **meaning** of `datatype`/`layout`/`capabilities`/`shape` | — | ✅ registry, subtype-check, schema validation, layout→reader dispatch, sniff/convert, viewer dispatch |

- The `artifacts` table **replaces the placeholder `datasets` table** (the DATA_MODEL "dataset ≡
  analysis-output ≡ typed artifact" unification). That migration + replacement is a **P1 deliverable**; P2
  gives the rows meaning.
- **Hard rule (guards the whole open-model):** `artifacts.datatype` is **`TEXT` validated against P2's live
  registry** — **no closed enum, no CHECK, no FK to a datatypes table.** Baking a closed enum re-closes the
  Galaxy model (the exact bug DATA_MODEL exists to fix). P1 must not do it; P2 ships a test asserting it
  didn't (R2).
- *This overrides any "P2-owns-the-table" stance.* One artifacts table (P1) + P2 as the pluggable type
  authority its ingest calls.

### DEC-2 — There is **no `datatypes` DB table.** The registry is in-process, code+manifest seeded.
New datatype = **a registry entry, no migration** (DATA_MODEL: "new data types = a new registry entry, no
core change"). Seed at boot via `#[distributed_slice(DATATYPES)]` (Rust) + a TS singleton — the proven in-repo
`STUDY_EXTENSIONS` / `AnalysisRegistry` / ziee `web_search catalog()` pattern (set-in-code; DB stores only
per-instance config, which datatypes don't even need). `artifacts.datatype` validated against the live
registry at ingest, not by a DB FK.

### DEC-3 — The registry lives in **P2**; its type contract is **surfaced through** `@cyto/workbench-api` (P5), which **consumes** P2 — not the reverse.
`@cyto/workbench-api` **does not exist yet** (a P5/Phase-1 extraction). So:
- **Registry logic + seed lattice + validation/dispatch = P2**, in **both languages**.
- **Near-term (pre-package)** it lives in app **core**: `server/src/modules/datatype/` (Rust) +
  `ui/src/core/datatypes/` (TS — deliberately `core/`, not a feature `modules/`, so it survives the P5
  package extraction unmoved).
- The **type contract** (`Datatype`/`StorageSpec`/`LayoutKind`/`ViewerRef`/`ConverterRef` + the subtype-check
  algorithm) is P2-authored; **when P5 extracts `@cyto/workbench-api`, it re-exports P2's contract as the
  `datatypes` contribution point** (alongside `analyses`/`plotTypes`). Resolves the PLANNING_INDEX dispute
  exactly: "datatype registry lives in P2, is consumed by P5's `@cyto/workbench-api`." **No hard block** on
  P5 — P2 ships standalone in core first.

## 2. Items

### Registry core
- **ITEM-1 — Type contract (Rust + TS).** `Datatype { id, extends?, schema, storage: StorageSpec, capabilities?,
  ingest?, converters?, viewers }`; `StorageSpec { layout: LayoutKind, format, selectorMap }`;
  `LayoutKind = ChunkedDense | ChunkedSparse{CSC|CSR} | ColumnarTable | Chunked1d | OpaqueAsIs`;
  `ViewerRef { viewKindId, consumes }`; `ConverterRef { from, to, run: Host|Sandbox, entry? }`. Authored once,
  mirrored Rust↔TS.
- **ITEM-2 — Registry + subtype-check.** Build-from-slice/singleton; `is_a(x,y)` walks `extends`;
  `accepts_match(datatype, selector{type, subtypesOf, capabilities})` = subtype ∧ capability check. Rust
  `registry.rs` (`#[distributed_slice(DATATYPES)]`); TS `DatatypeRegistry` singleton mirroring
  `modules/analysis/registry.ts` (`register/all/isA/accepts/viewersFor`).
- **ITEM-3 — Seed lattice (near-term 6 types, DEC-9).** `data` → `tabular` → `matrix` →
  {`single-cell/anndata`, `embedding`}; `clustering` → `metadata-column` → `tabular`. Self-registering in both
  langs. Capabilities: `sliceable`, `has-obs`. (bulk/spatial/variant/structure = later entries; seam open.)
- **ITEM-4 — Rust↔TS parity gate.** Shared golden fixture (`lattice_golden.json`: the seed lattice + a matrix
  of `is_a`/`accepts` cases) validated identically by a Rust test and a TS test — mirror
  `openapi::emit_ts::tests::types_ts_parity`. Prevents host-gating vs UI-picker divergence (R1).

### Typing the artifact (over P1's table)
- **ITEM-5 — Schema validation hook.** `validate.rs::validate(datatype, shape)` (reuse in-tree
  `schemars`/`jsonschema`); called from **P1's ingest** before a row lands. Also validates the `datatype`
  **string** against the live registry (unknown → typed 422). No enum/FK (DEC-1/DEC-2).
- **ITEM-6 — Sniffer.** `sniff.rs`: ordered ext+magic detection (Galaxy sniff order) → candidate datatype;
  wired into P1's artifact-create/upload route so an upload becomes a **typed source artifact**
  (`source=true`). Generalizes the current `dataset` `set_uploaded` flow.

### Storage layouts + data plane
- **ITEM-7 — Layout vocabulary + selector→index mapping.** `layout.rs`/`layouts.ts`: each `LayoutKind` + a
  datatype's `selectorMap` maps *semantic* selectors (gene→column, cell→row, locus→range) to layout indices.
  **Layout-keyed, never domain-keyed** (DEC-4) — single-cell expression is one `ChunkedSparse{CSC}` consumer,
  not privileged.
- **ITEM-8 — Client reader-dispatch (the default data path).** `core/datatypes/dataSource.ts` **generalizes
  viz `viz-core/data/wire.ts`** `DataSource`/`DatasetCatalog`: given (artifact, selector), issue HTTP-Range
  requests to **P1's authed byte-range endpoint** and decode **client-side** (zarrita for Zarr,
  DuckDB-WASM/Arrow for Parquet, igv.js/Mol* for as-is genomics/structure). Served formats (DEC-5): arrays→
  **Zarr v3**, tables→**Parquet**, self-indexed genomics/structure→**as-is**. **Rust needs no Zarr/HDF5 codec
  in the serving path** (bytes only).
- **ITEM-9 — `LayoutSlicer` server seam (deferred impl).** A trait keyed on `LayoutKind` for optional
  server-side Tier-2 typed slicing. **Not implemented near-term** — the client zarrita path (ITEM-8) covers
  the interactive case. Keep the seam; ship the simple case.

### Ingest transforms
- **ITEM-10 — Converter registry + host-lite converters.** `convert.rs`: `csv/tsv → Parquet`; `h5ad → Zarr`
  via **kerchunk-virtualize** (a small JSON reference index into the untouched `.h5` — **no rewrite, no
  sandbox**). This is the **P3-independent fallback** so the vertical slice's real anndata ingest isn't
  hard-blocked on compute (DEC-6/R3).
- **ITEM-11 — Sandbox converter dispatch (P3 seam).** Same `ConverterRef` registry dispatches `run: Sandbox`
  converters (`h5ad → AnnData-Zarr` full convert via anndata/zarr in the scientific rootfs) through P3's
  JobRunner. Implicit Galaxy auto-conversion (auto-insert an `A→B` edge when an analysis `accepts: B`)
  **declared but deferred** — explicit convert first.

### Viewers-per-datatype
- **ITEM-12 — Viewer dispatch resolver.** `viewers.ts::viewersFor(datatype)` (subtype-aware) → `ViewerRef[]`.
  **P2 dispatches, never renders** (DEC-7): a `ViewerRef.viewKindId` points at a renderer in **P7's view-kind
  registry** (deck.gl matrix-family) or an external viewer family (`molstar`/`igv`). Coordinate the
  `ViewerRef`/`consumes` contract with P7's `switch(CellKind) → registerViewKind` refactor.

### Introspection / surfaces
- **ITEM-13 — Introspection endpoints.** `GET /api/datatypes` (dump the live registry: lattice + capabilities
  + viewers) for UI pickers; `GET /api/artifacts/{id}/catalog` = a **typed catalog view** (P1 row + registry
  → the `DatasetCatalog`-shaped payload viz already expects). Feeds the artifact-ref pickers (Tier-2 form
  fields, PLATFORM §4.3) and P9's **MCP datatype/catalog resources** (the AI world-model).
- **ITEM-14 — P5 handoff.** When `@cyto/workbench-api` is extracted, re-export ITEM-1's contract as the
  `datatypes` contribution point; no logic moves (it's already in `core/`).

## 5. Dependencies

- **P1 (data-foundation) — HARD.** Needs the `artifacts` table + blob store + authed byte-Range endpoint +
  an ingest seam that calls P2 validate/sniff. P2 is a semantic layer *over* P1; it can be authored in
  parallel (registry/subtype/parity/seed = ITEM-1–4, 7, 12 have no P1 dep) but ITEM-5/6/8/13 integrate with P1.
- **P3 (compute) — SOFT (common-path).** Sandbox converters (ITEM-11, `h5ad→Zarr` full). Decoupled by the
  kerchunk host-lite fallback (ITEM-10) so real anndata ingest works without P3.
- **P5 (contribution-api) — CONSUMES P2.** Re-exports ITEM-1 as the `datatypes` contribution point (ITEM-14).
  No block (P2 ships in core first).
- **P7 (visualization) — JOINT contract.** `ViewerRef.viewKindId` resolves into P7's post-refactor view-kind
  registry. Agree `ViewerRef`/`consumes` before P7's switch→registry lands.
- **P9 (ai-mcp) — CONSUMES P2.** Datatype lattice + artifact catalog as MCP resources (ITEM-13).
- **P10/P11 — CONSUME P2.** Analysis `accepts`/`produces` gating + artifact-ref pickers call P2 subtype-check.

## 7. Decisions (summary — DEC-1..3 argued in §1)

- **DEC-4:** layouts keyed on **layout, not domain**; single-cell = one `ChunkedSparse` consumer, unprivileged.
- **DEC-5:** served formats Zarr v3 / Parquet / as-is; **client-side decode default**; server Tier-2 slicer
  deferred behind the `LayoutSlicer` seam; **Rust serving path is codec-free** (byte-Range only).
- **DEC-6:** converters split host-lite (csv→parquet, **h5ad→zarr kerchunk-virtualize**) vs sandbox
  (h5ad→zarr full, P3); **kerchunk is the P3-independent fallback**; implicit Galaxy auto-conversion deferred.
- **DEC-6b (sub):** to keep the **Rust serving/host path codec-free**, prefer routing even `csv→parquet`
  through a host-lite DuckDB step or the sandbox rather than pulling the Rust `parquet` codec into the server;
  confirm at implementation.
- **DEC-7:** P2 resolves datatype→`ViewerRef[]`; **P7/external families render.** P2 never renders.
- **DEC-8:** Rust/TS subtype-check + seed lattice guarded by a shared golden-fixture parity test.
- **DEC-9:** near-term seed = **6 types** (data, tabular, matrix, single-cell/anndata, embedding,
  clustering/metadata-column); bulk/spatial/variant/structure are later registry entries — seam open.

## 8. Risks

- **R1 Rust/TS registry drift** (host gating ≠ UI picker) → DEC-8 parity gate (ITEM-4).
- **R2 P1 boundary creep** — a closed `datatype` enum/CHECK/FK on `artifacts` re-closes the model. → DEC-1
  `TEXT`+registry-validation; ship a test asserting no enum/CHECK/FK on `artifacts.datatype`.
- **R3 common-path ingest depends on P3** (h5ad→zarr) → DEC-6 kerchunk host-lite fallback decouples the
  vertical slice.
- **R4 viewer-dispatch double-ownership with P7** → DEC-7 joint `ViewerRef`/`consumes` contract, agreed
  before P7's switch→registry refactor.
- **R5 `@cyto/workbench-api` absent (P5)** → DEC-3 ship in `core/`, extract later; no block.
- **R6 Rust Zarr/Parquet tooling maturity** — mitigated: serving is byte-Range only (no Rust codec); writes
  happen in Python/sandbox; DEC-6b keeps host codec-free.
- **R7 schema-validation scope creep** — near-term schemas validate **shape only**; keep minimal.
- **R8 migration ordering** — the `datasets→artifacts` replacement is P1's; P2 adds **no** migration.
  Coordinate the shared Phase-0 cutover with the P1 owner.

## 9. Test enumeration (for phase-3)

- **Rust unit:** `is_a` chains + `accepts_match` (subtype ∧ capability); sniff (ext+magic→datatype, ambiguous
  order); validate (good/bad shape, unknown-datatype→422); registry build-from-slice completeness.
- **Parity:** `lattice_golden.json` → Rust == TS (subtype + accepts matrix).
- **TS unit:** `DatatypeRegistry` isA/accepts/viewersFor; `dataSource` Range-URL construction per
  layout/selector (sparse gene-column, Parquet row-group, as-is passthrough).
- **Integration (with P1):** upload→sniff→typed source artifact row; `GET /api/datatypes`;
  `GET /api/artifacts/{id}/catalog` matches viz `DatasetCatalog` shape; kerchunk `h5ad` roundtrip
  (client reads a gene column via range).
- **Anti-regression:** `artifacts.datatype` is `TEXT`, no enum/CHECK/FK (guards DEC-1/R2).
