# P3 — Compute Scheduling (r2)

Scope: DESKTOP + SINGLE-BOX SERVER ONLY. Build the LOCAL bwrap arm behind open seams
(`ComputeBackend`, ingest/provenance sinks). Do NOT build remote/HPC/cloud — keep the seam.

Grounding (verified in code, not docs):
- `jobs` module is a FULL FCFS scheduler already: `JobRunner` trait + `StubJobRunner`
  (`runner.rs`), a claim/dispatch loop + per-job executor that drives a child (log-drain,
  1s CPU/RSS `ProcSampler` by pid, watch-based cancel, terminal persist) (`scheduler.rs`),
  SSE/metrics/logs (`sse.rs`/`runtime.rs`/`repository.rs`), and no-op `JobSyncSink`/`JobNotifier`
  seams (`seams.rs`). `Job{job_type, name, status, params:JSONB, pid}` (`models.rs`). The RUNNER
  is the stub; the queue is real. `job_type` is stored but NEVER dispatched on (no job-type→runner
  registry — the gap P3 closes).
- `sandbox` module ALREADY has `build_bwrap_argv` with **`ExtraMount`/`MountMode` plumbing**
  (`sandbox.rs`), the hardened `run_in_sandbox` (Linux; `--clearenv --unshare-net`, rootfs `usr/`
  RO, per-job 0700 workspace RW at `/home/analyst`, cgroup scope + optional seccomp pipe), and a
  BATCH service `run_analysis(pool, req{command,timeout}, extra_mounts) -> AnalysisResult`
  (`service.rs`). `run_in_sandbox` is **batch-capture** (waits, caps stdout/stderr to 1 MiB, returns);
  it does NOT stream to a live executor and it deletes the workspace on return.
- `rootfs` module: docker-built-at-build-time, `include_bytes!`-embedded, lazy squashfuse-mount
  (`ensure_ready`). Dockerfile is MINIMAL (Debian + `r-base-core` + `python3` + jsonlite);
  `ROOTFS_SCHEMA_VERSION=1`. No scanpy/anndata/leiden/harmony yet.
- Contract (DATA_MODEL §"produces manifest"; provenance DESIGN_CANDIDATES §B3.1): path-agnostic
  `script.py` reads slots→paths from a mounted `inputs.json`; **params+seed baked into the script
  body** (so `code_sha256` fingerprints template+params); outputs go to `/outputs/*` + a
  `manifest.json` mapping output paths → typed artifacts; host hashes+ingests outputs and records a
  run node. Code = content-addressed Postgres blobs (provenance-owned). `inputs.json` is DERIVED
  (slots→mounts for a run, slots→`data/` at export), never authoritative.

Boundary with other parts: P3 owns EXECUTION (spawn/stream), SCHEDULING (classes/pool/fair-share),
the ROOTFS env, and the `inputs.json`/outputs-`manifest.json` CONTRACT + `ExtraMount` plumbing. P3
hands off (via no-op seams) to (a) the foundation working-store/catalog for artifact INGEST and (b)
live8 provenance for run-node/code-blob RECORDING. P3 does not implement the catalog, the datatype
readers, or the provenance schema.

## Items
- **ITEM-1**: `AnalysisSpec` wire contract + params codec (`sandbox/spec.rs`). The typed shape an
  `analysis` job carries in `Job.params`: `{ script | code_ref, language(python|rscript), inputs:
  [{slot, artifact_ref|host_path, sandbox_subpath}], outputs_dir, produces:[{id,type,from}],
  schedule:{class, cpu, mem_bytes}, timeout_secs, seed }`. Parse/validate from `serde_json::Value`;
  reject absolute/`..`/non-`/inputs|/outputs` sandbox paths (path-injection guard). Pure + unit-testable.
- **ITEM-2**: `inputs.json` generation + script staging (`sandbox/spec.rs`). Given a resolved spec +
  a workspace dir, write `inputs.json` (path-agnostic slot→in-sandbox-path map, `{"inputs":{...},
  "outputs":{...}}`) and stage `script.py`/`script.R` into the 0700 workspace root. Params+seed are
  ALREADY in the script body (generated upstream / baked); P3 only binds paths. Deterministic bytes.
- **ITEM-3**: Outputs `manifest.json` parser + typed-output extraction (`sandbox/spec.rs`). After a
  run, read `<workspace>/outputs/manifest.json`, map each `{id,type,from}` to an absolute host path
  under the outputs dir, validate `from` stays under `/outputs` (no escape), return `Vec<ProducedOutput>`
  for the ingest sink. Missing manifest on exit-0 = a typed error (analysis contract violation).
- **ITEM-4**: `ExtraMount` input/output plumbing (`sandbox/spec.rs` → reuses existing `ExtraMount`).
  Resolve each input slot's host path (artifact-ref resolution is a seam call to the working store;
  host_path direct for now) → `ExtraMount{host_path, /inputs/<slot>, ReadOnly}`; create the RW outputs
  dir → `ExtraMount{outputs_host, /outputs, ReadWrite}`. Feed the existing `build_bwrap_argv` extra_mounts.
- **ITEM-5**: Streaming spawn variant `sandbox::spawn_analysis` (`sandbox/sandbox.rs` + `service.rs`).
  Factor the shared setup out of `run_in_sandbox` (identity, rootfs `ensure_ready`, caps promotion,
  cgroup scope, seccomp pipe, argv build) into a helper; add a spawn-only path that returns the live
  `tokio::process::Child` (stdout/stderr piped) **plus the owned guards** (cgroup scope, seccomp pipe,
  workspace guard) so the jobs executor drives log-drain/metric/cancel and the guards live as long as
  the child. Keep the batch `run_in_sandbox`/`run_analysis` for the ad-hoc REST `execute` path.
- **ITEM-6**: `ComputeBackend` seam + `LocalBwrapBackend` (`sandbox/backend.rs`, NEW). Trait
  `launch(&ResolvedRun) -> Result<LaunchedCompute{child, guards}>` — the §4.1.2 topology seam
  (local/remote/HPC land behind it later; only Local built). `LocalBwrapBackend` delegates to
  `spawn_analysis`. Non-Linux impl returns `SANDBOX_UNAVAILABLE` 503.
- **ITEM-7**: `SandboxJobRunner: JobRunner` + job-type dispatch (`jobs/runner.rs`). A `DispatchRunner`
  routing on `Job.job_type`: `"stub"`→`StubJobRunner` (kept), `"analysis"`→`SandboxJobRunner`.
  `SandboxJobRunner::spawn` decodes `AnalysisSpec` (ITEM-1), resolves mounts (ITEM-4), stages
  inputs.json+script (ITEM-2), and calls the selected `ComputeBackend` (ITEM-6). Closes the
  no-job-type-dispatch gap.
- **ITEM-8**: Extend `SpawnedJob` + add a post-exit `finalize` hook (`jobs/runner.rs` +
  `scheduler.rs`). `SpawnedJob{child, guards: Option<Box<dyn Send>>, workspace: Option<PathBuf>}`.
  The executor, on a terminal `Outcome`, calls `runner.finalize(&job, outcome, workspace)` → parse
  outputs manifest (ITEM-3) → `ArtifactIngestSink` (ITEM-11) → `RunRecorder` (ITEM-12) → then
  best-effort workspace cleanup. Guards drop when the executor frees `SpawnedJob`.
- **ITEM-9**: Scheduling classes — schema + model (`jobs/migrations/*`, `jobs/models.rs`). Add
  nullable columns `schedule_class TEXT` (`interactive|normal|batch`, default `normal`),
  `req_cpu INT`, `req_mem_bytes BIGINT`, and provenance-linkage `study_id UUID NULL`, `run_id UUID
  NULL` (coordinated with live8 provenance; P3 only adds the columns it schedules on). `ScheduleClass`
  enum + serde. Backfill existing rows to `normal`.
- **ITEM-10**: Class-aware + fair-share dispatch (`jobs/scheduler.rs` + `jobs/repository.rs`).
  Single pool, admin `max_concurrent` cap, plus `reserved_interactive_slots`: interactive jobs may
  use the whole pool; non-interactive jobs are capped at `max_concurrent - reserved_interactive_slots`
  running, so a burst of batch jobs never starves a watched reclustering. Replace the single
  `claim_next_queued` with a class+fairness-ordered claim: **order queued by (owner's current running
  count ASC, class priority DESC, created_at ASC)** — per-user weighted fair queuing within a class so
  one user's (or the AI agent's) burst can't starve others. Dispatch loop counts running per-class to
  honor the reservation. Near-FCFS on desktop (1 user, cap 1-2).
- **ITEM-11**: `ArtifactIngestSink` seam (`jobs/seams.rs`, no-op default). `ingest_outputs(job,
  &[ProducedOutput]) -> Vec<ArtifactId>` — the hand-off to the foundation working-store/catalog
  (content-hash + store + catalog row). No-op logs this round (mirrors `NoopJobSyncSink`); wired to
  the foundation's workstore ingest at merge.
- **ITEM-12**: `RunRecorder` seam (`jobs/seams.rs`, no-op default). `record_run(job, code, inputs,
  outputs, exit, timing) ` — the provenance hand-off (content-addressed code blob + run node +
  used/generated edges, live8 `feat/provenance` schema). No-op this round; wired at the provenance merge.
- **ITEM-13**: Per-class scheduler settings (`jobs/settings.rs` + `models.rs` + migration/route).
  Extend `job_settings` singleton with `reserved_interactive_slots INT` (default 1) alongside
  `max_concurrent_jobs`; expose in the existing GET/PUT settings route + admin UI field. Validated
  `0 <= reserved < max_concurrent`.
- **ITEM-14**: Scientific rootfs (`rootfs/Dockerfile` + `rootfs/version.rs` +
  `build_helper/sandbox_rootfs.rs`). Add the Python single-cell stack — `scanpy`, `anndata`,
  `leidenalg`, `harmonypy` (+ numpy/scipy/pandas/igraph deps) — via a pinned pip venv (or micromamba)
  in the rootfs stage. Bump `ROOTFS_SCHEMA_VERSION` 1→2 (kept in lockstep via the Dockerfile
  `--build-arg`). Verify import in the build (`python3 -c "import scanpy, anndata, leidenalg,
  harmonypy"`). Keep `|| true` fail-soft only for optional layers; the core stack must be present.
- **ITEM-15**: cgroup-sourced metrics for sandboxed jobs (`jobs/runtime.rs` / `sandbox/cgroup.rs`).
  When a cgroup scope exists, sample `memory.current` + `cpu.stat` from the scope instead of the
  bwrap-pid tree (pid sampling undercounts grandchildren). Fall back to `ProcSampler` when no cgroup.
  Feeds the existing `insert_metric`/SSE path unchanged.
- **ITEM-16**: Wire-up + install (`jobs/mod.rs`). Build the `ComputeBackend` (LocalBwrap),
  `DispatchRunner`, and install seams (`ArtifactIngestSink`/`RunRecorder` no-ops) in
  `JobsModule::init`; the scheduler uses the DispatchRunner instead of `StubJobRunner`.
- **ITEM-17**: Tests — unit (AnalysisSpec parse/validate + path-injection reject; inputs.json bytes;
  manifest parse + escape reject; ExtraMount resolution; class+fair-share ordering pure fn; reserved-
  slot arithmetic) reuse the existing argv tests; integration (Linux+rootfs-gated: an `analysis` job
  runs a scanpy leiden script end-to-end → outputs manifest parsed → ingest/record seams fire;
  interactive-vs-batch never head-of-line-blocks; fair-share across two owners). Non-Linux 503 path.

## Decisions
- **Keep BOTH execution paths**: batch `run_analysis` (ad-hoc REST `execute`, capture-and-return) AND streaming `spawn_analysis` (jobs, executor-driven). Don't collapse — different consumers.
- **`ComputeBackend` is the §4.1.2 topology seam; `JobRunner` is the jobs-module seam.** `SandboxJobRunner`(JobRunner) → `LocalBwrapBackend`(ComputeBackend). Local-only now; remote/HPC impl the same trait later — no rewrite.
- **Job-type dispatch via a `DispatchRunner`** (route on `Job.job_type`), not a global registry — minimal, matches the two current types (`stub`,`analysis`).
- **`SpawnedJob` carries opaque `guards: Box<dyn Send>`** (cgroup scope + seccomp pipe + workspace guard) so they outlive the spawn call for the child's whole life; dropped when the executor finishes.
- **Workspace lifetime**: the analysis job's OWN id is the `SandboxContext.job_id` (cgroup + provenance line up); the workspace SURVIVES past exit until `finalize` ingests outputs, THEN best-effort cleanup — unlike the batch path which deletes immediately.
- **Scheduling model**: single pool + `reserved_interactive_slots` (interactive may use the full pool; non-interactive capped at `cap - reserved`) + per-user weighted-fair claim ordering (owner running-count, class priority, created_at). Three classes `interactive|normal|batch`, one resource class `cpu-sandbox`. No multi-pool/GPU routing (deferred seam).
- **`inputs.json` = path-only binding**; params+seed baked in the script body (matches provenance §B3.1 so `code_sha256` fingerprints template+params). P3 does NOT author the script — it receives it (or a code_ref) and binds paths.
- **Outputs contract**: `/outputs/manifest.json` `{produces:[{id,type,from}]}`; missing on exit-0 = contract violation (fail the job). Ingest + provenance are seams (no-op default), NOT implemented in P3.
- **Rootfs schema bump 1→2** required (new packages); cargo clean + docker rebuild; the mount probe refuses a v1 rootfs against a v2 binary (existing behavior).
- **Non-Linux** analysis jobs 503 (sandbox is Linux-only); the scheduler marks them failed with a clear error.

## Risks
- **Ingest/provenance seams are unbuilt** (owned by other parts) — the END-TO-END artifact→catalog→graph path can't be integration-verified until the foundation lands. Mitigate: no-op capturing seams + assert the seam fires with the right outputs in tests; full E2E deferred to merge.
- **Rootfs image blowup**: scanpy+scipy+igraph+harmony ≈ 1–2 GB → embedded-binary size + build time. Mitigate: pinned wheels, `--no-install-recommends`, strip caches, zstd squashfs (already). May justify a "minimal vs full" rootfs flavor later (out of scope now).
- **Metric undercount**: bwrap-pid `ProcSampler` misses grandchildren; ITEM-15 (cgroup source) mitigates but only when cgroup delegation is present (desktop often `CgroupMode::None`) → rlimits-only accounting is approximate. Acceptable; flagged.
- **Fair-share edge cases**: an all-batch queue with `reserved` slots idle wastes capacity if no interactive ever arrives → reservation should be a SOFT cap (batch may use reserved slots when no interactive is queued). Encode in ITEM-10.
- **Workspace disk growth** if `finalize` fails before cleanup → orphaned per-job dirs. Mitigate: boot-time sweep of stale workspaces (extend the existing orphaned-running reset).
- **Schema-bump coordination**: bumping ROOTFS_SCHEMA_VERSION invalidates any cached extracted rootfs on dev boxes; document the `rm -rf` + cargo clean step.
- **`study_id`/`run_id` column ownership** overlaps live8 provenance — additive nullable columns only; do not define the provenance semantics here.

## Effort
Medium-Large. The queue/executor/argv/mount/rootfs-pipeline scaffolding all EXISTS — P3 is
integration + policy, not greenfield. Heaviest: the streaming-spawn refactor of `run_in_sandbox`
(guard lifetimes) and the scientific-rootfs build (long, iterative, size-sensitive). Scheduling
classes + fair-share are a bounded change to one claim query + the dispatch loop. Seams keep the
cross-part hand-offs cheap. ~17 items; unit-testable core, integration gated on Linux+rootfs.
