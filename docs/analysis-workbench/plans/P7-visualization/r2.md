# P7 — Visualization: adopt live3 `feat/visualization` as the canvas engine (r2)

Scope: **desktop + single-box server only** (BUILD_PLAN deployment table). Adopt live3's generic deck.gl
plotting library as the workbench center canvas; turn its **closed `switch(cell.kind)`** into an **open
runtime view-kind registry** that IS the P5 `plotTypes` contribution point; publish its conformance battery;
add viewer-per-datatype dispatch; keep Coordination-driven linked small-multiples + overlays.

Grounding facts (verified in `/data/pbya/txresbench/tmp/visualization-wt`, branch `feat/visualization`):
- `viz-core/` is a self-contained, deck.gl-only, **no-`@txresbench/*`** library (see the "viz-core rule" header
  comments). `adapter/` (Coordination.store, GridWorkspace.store via `@txresbench/framework/store-kit`,
  VisualizationPage, autosave, popout) is the only app-coupled layer.
- The closed points that make it library-extensible, not platform-extensible:
  1. `viz-core/grid/gridModel.ts` — `type CellKind = 'scatter'|'image'|'grid'|'violin'|'box'|'bar'|'dotplot'|'heatmap'|'volcano'|'histogram'` (closed union); `isDenseKind()` hardcodes `scatter||image`; `defaultBindings()` hardcodes chart-binding derivation; `swapCellContent()` hardcodes the display-field set.
  2. `viz-core/grid/CellView.tsx::ChartBody` — an **exhaustive `switch(cell.kind)`** with one static `import` per chart View (`ViolinView`…`VolcanoView`) + `Unsupported` fallback.
  3. `viz-core/grid/CellChrome.tsx::CELL_KIND_OPTIONS` — hardcoded kind list feeding the switcher `<select>`.
  4. `viz-core/conformance/viewKindBattery.test.ts` — `const KIND: Record<CellKind, KindRunner>` mirrors the union (compile-time exhaustiveness), asserting invariants from `viz-core/conformance/invariants.ts`.
  5. `viz-core/data/wire.ts::DataSource` — the typed-binary data seam (already "drops onto the real octet endpoints"); `VisualizationPage` backs it with `FixtureSource`.
- Coordination already exists: `adapter/Coordination.store.ts` (viewStates/pointSelection/selectionOrigin/colorScales/gridLinked) + `viz-core/coordination/*` — the brushing-and-linking + linked-color-scale substrate. Overlays exist as the per-cell `graphOverlay` toggle wired in `GridWorkspace.tsx` (`buildGraphOverlay` → `<cellId>::graph-*` layers).

## Items

- **ITEM-1**: Adopt `feat/visualization` into the platform tree unchanged. Land live3 to main first (per BUILD_PLAN re-sequencing step 1), then relocate `viz-core/` + `adapter/` under the workbench module (`modules/workbench/canvas/`). `viz-core` stays `@txresbench/*`-free (keep the rule); only `adapter/` imports platform APIs. No behavior change — this is a move + re-home, gated by the existing viz test suite staying green.
- **ITEM-2**: Introduce the **`ViewKindDescriptor`** type + a runtime **`registerViewKind` / `listViewKinds` / `getViewKind`** registry (`viz-core/registry/viewKindRegistry.ts`). A descriptor = `{ id, title, dense, dataContract, render(ctx): ReactNode, defaultBindings(catalog), conformance(caseInputs): void, swapFields?: (keyof GridCell)[] }`. Registry is a plain module-level Map with duplicate-id guard (mirror `showcase/registry.ts::registerStory`). This registry IS the P5 `plotTypes` contribution point (§4.2 "plotTypes == the viz package's view-kind registry").
- **ITEM-3**: Refactor `gridModel.ts` from the closed union to registry-driven. `CellKind` becomes `string` (a registered id); `isDenseKind(kind)` reads `getViewKind(kind)?.dense ?? false`; `defaultBindings` delegates to the descriptor (or keeps the catalog-derived default as a fallback for chart-family kinds); `swapCellContent` swaps the descriptor's `swapFields` (default: `kind`+`colorBy`+`linkColorScale`+`graphOverlay`) so a new view-kind's per-cell state travels on swap. Keep the pure/no-React contract (still node-unit-testable).
- **ITEM-4**: Replace `CellView.tsx::ChartBody`'s exhaustive `switch` with `getViewKind(cell.kind).render({ cell, source, catalog, rect, positions, colors, colorEpoch })`. Chart Views become **registered descriptors** (each `charts/*View.tsx` gets a co-located `register()` that binds its render + `dataContract` + `conformance`); the static imports in `CellView` go away (kinds self-register by import side-effect, like the showcase stories). Keep the `Unsupported` fallback for an unregistered id (never crash — preserves the current contract).
- **ITEM-5**: Register the 10 **built-in view-kinds** as descriptors — the dense pair (`scatter`, `image`) + the chart set (`violin`, `box`, `bar`, `histogram`, `dotplot`, `heatmap`, `volcano`) + the `grid` container-cell — each declaring its `dataContract` (coordinates N×2 / a `values`/continuous column / a `matrix` rows×cols / `groups`, mapped to the `DataSource`/`DatasetCatalog` surface) and its `conformance` closure (moved verbatim from the `KIND` runner table). One registration barrel (`viz-core/viewkinds/index.ts`).
- **ITEM-6**: Make `CellChrome.tsx::CELL_KIND_OPTIONS` read `listViewKinds()` (id + title) instead of the hardcoded array, so the view-kind switcher `<select>` renders exactly the registered set (built-ins today; contributed kinds later).
- **ITEM-7**: Refactor `viewKindBattery.test.ts` from `Record<CellKind, KindRunner>` to **iterate `listViewKinds()`**, calling each descriptor's `conformance(buildCase(...))` over the fast-check property runs + the degenerate + real-`FixtureSource` wire paths. The compile-time exhaustiveness (a `Record` over a closed union) is replaced by a **runtime coverage assertion**: every registered id has a `conformance` fn, and the battery runs it. ## Decisions
- **`CellKind` closed union → `string` id, resolved by the registry** (not a discriminated union nor a plugin enum). Matches VS Code `contributes` / napari `npe2` open-registry model; `Unsupported` fallback preserves crash-safety.
- **View-kinds self-register by import side-effect** (like `showcase/registry.ts` stories), not a central static list. A barrel imports the built-ins; the switch's static imports disappear.
- **Registry lives in `viz-core` (`@txresbench/*`-free); `@txresbench/workbench-api` RE-EXPORTS it** — keeps viz-core a standalone package while P5 owns the public contribution surface. The descriptor type is the shared contract.
- **Conformance is a per-descriptor closure the published harness drives**, NOT a hand-maintained `Record`. Runtime coverage assertion replaces compile-time union exhaustiveness. This is the automatic acceptance gate for third-party plots (§4.2).
- **deck.gl view-kinds = the `matrix` viewer FAMILY, one of many** (DATA_MODEL). `plotTypes` generalizes to a viewer-registry-keyed-by-datatype; near-term only the matrix family is populated, genome/structure/network families are deferred seams (no SVG/Vega — the no-SVG law holds; the safe third-party tier is "parameterize a view-kind" + "new deck.gl-layer view-kind, battery-gated", NOT Vega vs iframe).
- **Coordination store is adopted, not replaced.** Its `pointSelection` becomes the platform `CellSet`; the platform selection API is a thin bridge over it, not a parallel model (avoids the N-selection-models failure §4.4).
- **Overlays are a registry** (graph + selection-highlight first), reusing the `<cellId>::`-prefix layer routing — so interactive tools (annotation/gating/trajectory) contribute overlays without touching the grid.
- **Scope: matrix-family single-cell only near-term.** Populate the datatype/viewer/overlay seams incrementally (DATA_MODEL "design the seam open now; populate it incrementally").

## Risks
- **Registry timing vs the compile-time-exhaustive battery.** Losing the `Record<CellKind,…>` compile guard means a registered kind could ship without a `conformance` fn. Mitigate: the runtime coverage assertion (ITEM-7) + the register-time harness run (ITEM-8) fail loudly; keep it in `just check`.
- **`@txresbench/workbench-api` boundary (P5 co-ownership).** The `plotTypes` registry shape must be agreed with P5 or it's built twice. Mitigate: P7 defines the descriptor in viz-core; P5 re-exports — single source.
- **DataSource↔P1 impedance.** `wire.ts`'s framings (interleaved positions, CSC sparse column, u16 codes) must match P1's octet endpoints exactly, or the "no rewrite" promise breaks. Mitigate: `wire.ts` was designed against `DATA_STORAGE_REDESIGN` §2/§3.4 — hold P1 to those framings; the decoders are the contract test.
- **Adapter store-kit coupling on move.** `Coordination`/`GridWorkspace` stores use `@txresbench/framework/store-kit` — re-homing must keep the store-kit import path valid in the platform tree (per the store-kit sweep). Mitigate: move adapter/ intact; viz-core stays framework-free.
- **Pop-out currently renders a scatter fixture regardless of `cell.kind`** (noted in CellView C3a comment). Generalizing pop-out to the actual view-kind is now easy via the registry but is real work — flag as a follow-on, not a P7 blocker.
- **Battery is CPU/pure-math only** (GPU `*Gpu` parity proven in the browser harness). A contributed view-kind's GPU path isn't structurally gated — document that the battery validates the pure builders, not shaders.
