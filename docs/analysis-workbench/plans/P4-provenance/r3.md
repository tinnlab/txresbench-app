# P4 — Provenance & Reproducible Export (r3)

Scope: **desktop + single-box server only** (local bwrap sandbox verify, local-FS bundle output, DOI optional
external call). Integrates live8 `feat/provenance` (design-only; NO code yet — verified `git diff 177f909 HEAD`
touches only `.lifecycle/`). Grounds in PLATFORM_ARCHITECTURE §0.6, DATA_MODEL (multi-output provenance §), and
live8 DESIGN_CANDIDATES §B1/§B2/§B3/§B3.1 + Part F decisions.

---

## Ownership boundary — the headline decision (resolves the P1↔P4 dispute)

**Position: the GRAPH is P1's; the REPRODUCIBILITY LAYER is P4's. P4 does NOT create
`provenance_runs`/`provenance_artifacts`/`provenance_edges`.**

Reasoning: DATA_MODEL is explicit — *"This IS live8's provenance graph generalized: nodes = typed artifacts,
edges = analyses, datasets = roots. One graph does lineage, composition, and the dataset/analysis model."* —
and BUILD_PLAN §0c — *"the catalog's derivation edges ARE the provenance graph."* Availability-gating,
recipe-ordering, and lineage/reproduce-export must all read **one** graph; a parallel `provenance_*` triple is
a two-sources-of-truth divergence at exactly that seam. live8's original "provenance-owned triple" stance was
**explicitly contingent** on the catalog being *not-yet-built* ("decoupled from the not-yet-built catalog",
DEC-FOUNDATION). P1 now builds it → that contingency is gone → **adopt live8's node/edge MODEL (run=Activity,
artifact=Entity keyed by content-hash, `used`/`wasGeneratedBy`, three root kinds + closure invariant,
append-only re-run branching) but REALIZE it in P1's catalog tables.**

What **P4 owns** (its own tables/logic, none of which duplicate the graph):
1. **The capture LOGIC** — the `ProvenanceCapture` seam that *writes* graph rows into P1's tables at the two
   chokepoints (compute + interaction), plus the provenance-only enrichment.
2. **`provenance_code_blobs`** — content-addressed script store (graph *metadata*, not a data artifact).
3. **Per-run reproducibility enrichment** (env fingerprint / rootfs sha256 / lockfile / generator id+version) —
   sidecar `provenance_run_repro(run_id PK FK …)`, so P4 evolves without altering P1's core run schema.
4. **Everything downstream of the graph:** reproduce-script, methods text, RO-Crate, bundle, verify certificate,
   DOI, `provenance_settings`, the Reproducibility panel.

Net seam: **P1 owns schema + the `WITH RECURSIVE` backward walk (read); P4 owns write-at-chokepoint + all
publish/verify.** (Recorded as **DEC-OWN**.)

## Items

- **ITEM-1**: Adopt-not-duplicate graph. Consume P1's catalog run/artifact/edge tables + backward-walk query
  as the provenance graph. Provide a thin `provenance::graph` read-facade (typed views: `RunNode`,
  `ArtifactNode{content_hash}`, `used`/`wasGeneratedBy`) over P1's rows so P4 code (export/verify) is decoupled
  from P1's column names. NO new graph tables.
- **ITEM-2**: `provenance_code_blobs` table (migration): `sha256 PK, language, source TEXT, byte_len, created_at`.
  Content-addressed, deduped by hash (a step ≈ 1–10 KB text; hundreds of runs × few KB, deduped, < few MB/study
  → Postgres, NOT ziee-file). Referenced by a `code_sha256` written onto the run row (or the repro sidecar).
- **ITEM-3**: `provenance_run_repro` sidecar (1:1 with a catalog run): `run_id PK FK, code_sha256 FK,
  generator_id, generator_version, env_rootfs_sha256, lockfile_json (versions.json receipt), seed,
  inputs_json_derived (nullable cache), captured_at`. Keeps P1's core run schema untouched; P4-owned.
- **ITEM-4**: **ProvenanceCapture seam around the compute chokepoint.** A capture hook wrapping the
  `JobRunner`→`sandbox::run_analysis` path: on run start hash+store the emitted `script.py` → code blob (so even
  a FAILED run has code captured); on completion record the run row (params/seed/command/timing/user/exit into
  P1) + the repro sidecar (code_sha256, generator id+ver, env fingerprint, lockfile) + `used`/`wasGeneratedBy`
  edges + the **per-artifact content hash + set-valued output signature** (`{(output-id, hash)}` from the
  `produces` manifest — DATA_MODEL fan-out). Ordering: **generate → hash → store blob → run → record node**.
- **ITEM-5**: **Closure enforcement at capture.** Reject/flag a run whose declared input is not a known
  {upload · prior-analysis-output · pinned reference resource} — the three-branch resolver that records the
  `used` edge is the enforcement point (closes the "ambient input" hole; guarantees every backward walk
  terminates at roots).
- **ITEM-6**: **Reference-resource root nodes.** A small `provenance_reference_resources` (or reuse P1 root
  artifacts tagged `kind=reference`): versioned, hash-identified system/library inputs (reference genome+annot,
  atlas, gene set) as first-class roots so journal-required inputs are captured. (Thin; may fold into P1 root
  artifacts if P1 models `source_kind`.)
- **ITEM-7**: **Interaction chokepoint capture** ("record selection" API). Every state-mutating manual action
  (selection/gate/group/annotate/subset — §B2 vocabulary) lands as a `selection.*`/`annotate.*`/… run node
  (`Activity`) + an **emitted** hashed code blob + a `used` edge to the exact input artifact by content-hash +
  an output edge to the derived artifact (cell-set/group/annotation). Env = "app + emitter version" (NOT rootfs
  — applied in-app, not sandboxed).
- **ITEM-8**: **Selection-as-RECIPE storage** (scale-safe). A predicate selection stores `{predicate} +
  {pinned input-artifact content-hash}` (~1 KB, O(1) in cell count) — NEVER a materialized 10M-cell mask (§3.9
  bitmask is runtime-only, re-derived on demand, not persisted). Set-algebra/groups = `{operand recipe refs} +
  {op}`. **Freehand only** = a small explicit id-list. The recipe reproduces exactly because the input is pinned
  by hash → deterministic replay, no drift, no stored fallback set. (Predicate DSL itself is P8; P4 stores the
  recipe on the run node + emits its code.)
- **ITEM-9**: **Open interaction-action registry** (future-proofing, §B2). A registry keyed by action-type →
  `{versioned spec schema, code emitter, apply fn, fidelity class ∈ declarative|identity-based|view-only}`, so
  each future manual feature plugs into the SAME capture seam. Build only the action types whose features exist
  (selection/group/annotate for the vertical slice); reserve the vocabulary.
- **ITEM-10**: **Reproduce-script generator.** Topological sort of the backward closure → per-step
  **path-agnostic** `script.py` fragments (from `code_blobs` by `code_sha256`, **never regenerated** from
  current templates) + a `run.sh` driver (Code-Ocean capsule shape). Manual-action emitters drop inline in topo
  order (predicate code / freehand id-list), indistinguishable from a computed step; ship `points_in_polygon`
  etc. as harness helpers.
- **ITEM-11**: **`inputs.json` derivation.** Per-run tiny path-binding manifest mapping the script's logical
  input/output *slots* → paths — **derived from the graph edges** (authoritative = the `used` edge by id+hash),
  generated fresh two ways: slots→sandbox mounts (capture/verify) and slots→`data/` (export bundle). Params +
  seed are baked into the script body (so `code_sha256` fingerprints "template + exact params"), NOT in
  `inputs.json`.
- **ITEM-12**: **Methods-text generator.** Templated deterministic single-cell methods paragraph from the
  run-node attributes (tool+version, params, seed, thresholds, selections narrated) + DAS/KRT (data- &
  key-resources tables). Optional LLM-assisted polish via ziee chat/assistants (**OFF by default** so the
  artifact stays deterministic). Reuse the embedded **pandoc** (already vendored for `citations`) for format
  emit where useful.
- **ITEM-13**: **RO-Crate manifest.** Phase-1 = RO-Crate-*shaped* bespoke `manifest.json` (fields chosen to be
  mechanically convertible) → phase-2 upgrade **in place** to full **Workflow-Run RO-Crate** (Provenance Run
  Crate profile, `ro-crate-metadata.json`). PROV as the model, not the wire format.
- **ITEM-14**: **Export bundle assembler** (BagIt-RO shape): `data/` (the walk's content-addressed artifacts,
  fetched from P1/results-store) + per-step `script.py` + `run.sh` + bundle-relative `inputs.json` + env spec
  (rootfs sha256 + lockfile) + `methods.md` + `manifest.json` + `REPRODUCING.md`. **Export scoping = which root
  you walk from**: single analysis/figure (default backward closure) · a set of analyses · whole study (union of
  leaf closures). Sibling analyses the target doesn't `use` are excluded (per-analysis code fragments — capture
  requirement from ITEM-4).
- **ITEM-15**: **Env-pinning + readiness checklist** (phase-1 verification tier). Capture the full rootfs
  sha256 + an in-sandbox lockfile/`versions.json` (sessionInfo receipt) per run; a Reproducibility-panel
  readiness checklist (inputs hashed? code captured? env pinned? all roots have provenance?).
- **ITEM-16**: **DEC-ROOTFS-DIGEST — surface the FULL rootfs sha256.** Today only a 12-char prefix is exposed
  at sandbox status; the run record needs the full `.sqfs-sha`. Add a full-digest field (non-breaking API
  addition) in the `rootfs`/`sandbox` status so capture can stamp it.
- **ITEM-17**: **In-sandbox re-run VERIFICATION + tolerance-diff certificate** (phase-3 tier, the
  differentiator). Re-mount the same rootfs, run the bundle's `run.sh` against `data/`, diff regenerated vs
  recorded outputs — check the **set-valued output signature** (all N artifact hashes) under a **statistical
  equivalence** tolerance (honest: NOT bit-exact — A2). Emit a "Reproduced ✓" certificate. Reuses ziee's own
  isolated headless sandbox (the wedge Code Ocean/CODECHECK sell as a service).
- **ITEM-18**: **Verification status persistence + surfacing.** `provenance_verifications(id, target_run_id,
  status ∈ pending|reproduced|diverged|error, tolerance, diff_report_json, cert_ref, verified_at)` + a
  **`VerificationBadge`** in the UI + a `SyncEntity::ProvenanceVerification` (Create/Update, owner/study-scoped).
- **ITEM-19**: **DOI deposit** (phase-2, optional, off by default). Zenodo/DataCite client (4-call flow) behind
  a seam; creds from settings via `common::secret`; deposits the bundle, returns a DOI stamped onto the export
  record. Desktop/1-box: an outbound HTTPS call, SSRF-safe (fixed public host).
- **ITEM-20**: **`provenance_settings` singleton** (DEC-SETTINGS, mandatory — mirrors
  `code_sandbox_settings`/`session_settings`): `verify_on_reproduce` toggle, re-run time/size budget caps,
  tolerance default, bundle+certificate retention days, DOI provider+creds (secret), methods-LLM-polish toggle.
  Migration + read-at-use with cache invalidation + REST `GET/PUT /api/provenance/settings` gated
  `provenance::settings::{read,manage}` + `SyncEntity::ProvenanceSettings` + admin card + bounds validation.
- **ITEM-21**: **Provenance study-extension registration.** Register via `#[distributed_slice(STUDY_EXTENSIONS)]`
  (+ `STUDY_SLOTS`); implement `on_study_deleted` (delete code blobs/repro sidecars/verifications/bundles for
  the study — via the shared delete chokepoint `delete_study_with_extensions`) + `on_study_duplicated`
  (deep-copy graph refs). Provenance data is study-scoped like every other extension layer.
- **ITEM-22**: **REST surface** (owner/study-scoped, foreign→404): `GET /api/provenance/graph?target=<run>`
  (walk), `POST /api/provenance/export` (build bundle, scope param), `GET /api/provenance/export/{id}` (download),
  `POST /api/provenance/verify`, `GET /api/provenance/verifications`, `POST /api/provenance/doi`, settings
  GET/PUT. All gated by the perms below.
- **ITEM-23**: **Permissions** — `provenance::read` (Users, graph+panel), `provenance::export`,
  `provenance::verify`, `provenance::doi`, `provenance::settings::{read,manage}` (admins via `*`). Migration
  grants read/export/verify to the study-role editor path; A9 backend-deny + A10 restricted-user e2e.
- **ITEM-24**: **Reproducibility panel (UI).** Workbench right-dock panel: lineage graph view (walk), readiness
  checklist, Export (scope picker → bundle download), Verify button + badge, DOI affordance. `ui/src/modules/
  provenance/` (stores + panel + export drawer + badge + settings admin card). Surfaces live5's phase-3
  export/verify affordances (DEC-OVERLAP-LIVE5 — live5 is UX-only; P4 owns the layer).
- **ITEM-25**: **Per-figure "cite this exact result" minimal capsule** (later delighter slice). A figure spec
  stamps back to its source run(s); export the minimal backward closure for that one figure as a citeable
  capsule. Deferred past the phase-1 study bundle.

## Decisions

- **DEC-OWN** (headline, above): graph = P1's catalog (single source of truth); P4 owns capture-logic +
  reproducibility layer + `provenance_code_blobs` + repro sidecar + settings. NO `provenance_runs/artifacts/
  edges` triple. Overrides live8's original decoupled-triple stance (contingent on a non-existent catalog).
- **DEC-CAPTURE** — passive auto-capture at the two chokepoints (compute + interaction). "Provenance for free"
  is the entire wedge; explicit/opt-in capture reintroduces the effort tax that kills adoption.
- **DEC-CODE-BLOB** — code stored as content-addressed Postgres text blobs (`provenance_code_blobs`, sha256 PK,
  deduped), NOT ziee-file (that's for large uploads), NOT the results-store (that's data artifacts). Code is
  graph metadata.
- **DEC-ONE-CODE-PATH** — the emitted script that RUNS a step IS the captured/exported code; export assembles
  the *stored* per-run blob (never regenerates from current templates → a later template change can't alter a
  captured run). Path-agnostic scripts + derived `inputs.json` make "code that ran == code exported" literal
  (no path rewriting).
- **DEC-SCOPE** — the ANALYSIS is the provenance unit, the JOB is the execution unit (a multi-analysis job =
  N run nodes; one analysis run = one run node fanning out to N artifact edges). Export = backward closure from
  the target analysis only; capture requires per-analysis code fragments for batched jobs.
- **DEC-RECIPE** — selections stored as recipe (predicate + pinned input hash), size-independent of cell count;
  §3.9 bitmask is runtime-only; freehand-only stores a small id-list.
- **DEC-VERIFY** — env-pinning (phase 1) → in-sandbox re-run + tolerance-diff certificate (phase 3). Target =
  **statistical equivalence under a pinned environment**, NOT bit-exact (honest framing mandatory).
- **DEC-MANIFEST** — RO-Crate-shaped bespoke JSON (phase 1) → full WRROC Provenance Run Crate (phase 2, upgrade
  in place); PROV as the model not the wire format.
- **DEC-DELIVERY** — downloadable BagIt-RO bundle (all phases); Zenodo/DataCite DOI optional (phase 2); capsule
  layout supports the phase-3 re-run.
- **DEC-METHODS** — templated deterministic default + optional LLM polish (OFF by default, deterministic
  artifact).
- **DEC-GRANULARITY** — per-run capture + per-study bundle; per-figure "cite this result" capsule later.
- **DEC-SETTINGS** — an admin `provenance_settings` singleton (verify toggle, budgets, tolerance, retention,
  DOI creds, LLM-polish toggle), NOT bare constants.
- **DEC-ROOTFS-DIGEST** — surface the FULL rootfs sha256 (today only a 12-char prefix), non-breaking API add.
- **DEC-SCOPE-DEPLOY** — desktop/1-box: verify re-runs on the local bwrap sandbox; bundle writes to local FS;
  DOI is the only outbound call. Remote/HPC verify deferred behind the same seam.

## Risks

- **Foundation not built (highest).** P1 catalog + P3 JobRunner→sandbox + scientific rootfs are the critical
  path; P4 is blocked until they land (BUILD_PLAN DEC-FOUNDATION). Mitigate: build the graph facade + code-blob
  store + export generators against a small fixture graph early; wire capture last.
- **Two-source-of-truth regression.** If any P4 code writes graph nodes/edges outside P1's tables, lineage
  diverges. Mitigate: DEC-OWN + the facade is the only write path; enforce in review/A-audit.
- **Verify nondeterminism.** Single-cell tools are seed/version/thread sensitive (B10); bit-exact is
  unachievable → tolerance/statistical-equivalence framing + pinned seed + `*_NUM_THREADS=1` in the harness
  preamble; surface tolerance in settings. Risk of false "diverged" if tolerance mis-set.
- **Verify resource budget.** Re-running a whole chain can be expensive on a 1-box desktop; the export scoping
  (backward closure only, not all jobs/dead-ends) + settings time/size caps bound it.
- **Recipe drift.** A selection recipe only reproduces if its input is pinned by content-hash AND that artifact
  is retained. Mitigate: closure enforcement (ITEM-5) + append-only (never GC an artifact on a live lineage
  path) — coordinate with P1/P10 blob-GC.
- **Batched-job code capture.** A non-decomposable monolith job breaks per-analysis code scoping; fallback =
  ship the whole job's code, mark unused outputs "also produced, not used by this export" (over-inclusive but
  honest).
- **DOI external dependency.** Zenodo/DataCite creds + availability; keep off by default, degrade gracefully,
  never block export on DOI.
- **Rootfs digest API change.** Surfacing the full sha256 must not break existing sandbox-status consumers →
  additive field only.
- **Large bundle data on 1-box.** A whole-study bundle can be large; default to the target-figure backward
  closure, offer whole-study explicitly.
