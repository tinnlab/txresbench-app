# P4 — Provenance & Reproducible Export (r2)

Scope: the lineage backbone (run nodes · content-addressed code blobs · path-agnostic `inputs.json` ·
output/derivation edges) + selection-as-recipe + reproduce/export (script · methods · RO-Crate · env-pin ·
in-sandbox re-run verification badge). Desktop + single-box server only.

**Integration reality:** live8's `feat/provenance` branch is **DESIGN-ONLY** (no code — only
`.lifecycle/provenance/DESIGN_CANDIDATES.md` §B1/§B2/§B3 + DEC-GRAPH…DEC-OVERLAP). So there is **nothing to
`git`-adopt**; we **adopt its design verbatim as the spec** (Candidate D, MVP-first) and **build all the code**.
The reusable *code* comes from the txresbench host SDK + the txr worktree, listed under Reuse.

## Items

- **ITEM-1**: `provenance` study-extension module scaffold. Backend `#[distributed_slice(STUDY_EXTENSIONS)]`
  entry (mirror `dataset/study_extension/extension.rs`, order ~45) with `register_routes` / `on_study_deleted`
  (delete provenance rows + bundles/blobs for the study, in-tx before study delete) / `on_study_duplicated`
  (copy graph rows). FE `modules/provenance/study-extension/extension.tsx` registering a `study_nav`
  "Reproducibility" section + `detail_panels` panel + `card_tags` "reproducible" badge. Perms
  `provenance::{use,settings::read,settings::manage}` + idempotent `_grants.sql` to `Users`.
  `SyncEntity::Provenance*` (notify-and-refetch, `Audience::owner`). Zero study-core edits.

- **ITEM-2**: Provenance schema (colocated migrations `2026072x…`, latest is `202607190005`). Tables:
  `provenance_code_blobs(sha256 PK, language, source TEXT, created_at)` (content-addressed, deduped);
  `provenance_runs(id, study_id, owner_id, job_id NULL, analysis_id, kind, code_sha256 FK, generator_id,
  generator_version, env_digest, seed, params JSONB, command, started_at, finished_at, exit_code, status)`;
  `provenance_artifacts(id, study_id, content_hash, node_kind ['upload'|'analysis_output'|'reference'|
  'cell_set'], catalog_ref NULL, storage_ref, meta JSONB)`; `provenance_edges(run_id, artifact_id, edge_kind
  ['used'|'wasGeneratedBy'])`; `provenance_selections(id, run_id, fidelity ['declarative'|'identity'|'view'],
  recipe JSONB, input_artifact_hash)`. Append-only (no update-in-place; re-runs = new run node).

- **ITEM-3**: `ProvenanceCapture` seam wrapping the P1/P3 compute chokepoint (the `JobRunner`→
  `sandbox::run_analysis` spawn+finish). ONE insertion point captures per step: params (`Job.params`), the
  exact command, code blob (order: **generate → hash → store blob → run refs `code_sha256` → record run node**
  so even a FAILED run has its code), env digest (full rootfs sha256 — ITEM-6), seed, timing
  (`started_at/finished_at`), acting user (`owner_id`), exit + logs. On finish: hash each declared `/outputs/*`
  per the `produces` manifest and record **one run node → N `wasGeneratedBy` artifact edges** (multi-output
  fan-out, `produce-atomically`); ancillary files (logs/temp) attach as run metadata, NOT graph nodes. Seam
  exposed as a trait/hook so P1's compute path calls it with no per-analysis-type duplication.

- **ITEM-4**: Path-agnostic `inputs.json` contract + input resolution. A step declares logical input refs
  (`{upload_id}`/`{analysis_output_id}`/`{reference_resource_id}`); the resolver maps each to a host path,
  mounts RO via `ExtraMount`, and **records the `used` edge at resolution** (three branches = the closure
  invariant). `inputs.json` is a slots→paths manifest ONLY (params/seed baked in the script body, not here);
  generated fresh slots→mounts for the sandbox run, slots→`data/` at export → **byte-identical script both
  places, no export-time path rewriting**. Enforce closure: reject a job whose declared input is not a known
  upload/artifact/reference.

- **ITEM-5**: Root nodes carry provenance at ingest. Add sha256 + uploader + timestamp + original filename +
  optional external accession/DOI to `dataset`/`txresbench-file` upload (upload is a checksum-less stub today →
  greenfield). Register **pinned external reference resources** (genome+annotation e.g. GRCh38+GENCODE v45,
  label-transfer atlas, gene sets) as first-class versioned ROOT artifact nodes. Both are `wasGeneratedBy`-less
  roots → every backward walk terminates.

- **ITEM-6**: Surface the FULL rootfs sha256 (DEC-ROOTFS-DIGEST). Today `content_version()` exposes only a
  12-char prefix at `/sandbox/status`; the run record needs the full `.sqfs-sha`. Small additive `rootfs`
  change (new field on `RootfsStatus` + a `full_content_hash()` accessor) — non-breaking. Env digest =
  `rootfs_sha256 + dockerfile_sha + optional in-sandbox lockfile hash`.

- **ITEM-7**: Selection-as-recipe capture (the second capture chokepoint — the interaction one). A "record
  selection" API the Explorer calls on a state-mutating gesture → a `selection.*` run node + `used` edge to the
  **source artifact by content hash** + output `cell-set` artifact edge. Store the **RECIPE, not a materialized
  set** (size-independent, studies reach ~10M cells): declarative predicate (`{polygon+embedding-hash}` /
  `{col,op,val}` / `{clustering_ref,labels}`) OR set-op (`{operand refs}+op`) — reproduces exactly because the
  input is pinned by hash; **freehand-only** stores a small explicit id-list. Emitted (not executed) code blob
  (`sel = points_in_polygon(ad.obsm['X_umap'], poly)`), env = app+emitter version. Interaction-action registry
  is OPEN (§B2 vocabulary) so each future manual feature plugs the same seam. Consumes P8's cell-set predicate
  DSL as the recipe wire format.

- **ITEM-8**: Backward-walk retrieval + export scoping. Postgres `WITH RECURSIVE` walk over `provenance_edges`
  from a target artifact to roots → the sub-DAG. **Export unit = the ANALYSIS** (a multi-analysis job = N run
  nodes): default scope = backward closure from ONE target analysis/figure; sibling outputs the target didn't
  `use` are excluded from *data/code carried*, but re-run regenerates the whole atomic set. Reachability
  distinguishes used-vs-dead outputs. Scope selector = which root(s) to walk from (one analysis · a set · whole
  study = union of leaf closures).

- **ITEM-9**: Reproduce-script generator. Topological sort of the sub-DAG → a `run.sh` driver (Code-Ocean
  capsule shape) + the exact per-step scripts pulled from `provenance_code_blobs` by `code_sha256` (never
  regenerated from current templates — a later template change can't alter a captured run) + a bundle-relative
  `inputs.json` (slots→`data/`) + a harness preamble (seed + `OMP/OPENBLAS/MKL_NUM_THREADS=1` + selection
  helpers like `points_in_polygon`). Manual/selection steps drop inline in topo order, indistinguishable from
  computed steps.

- **ITEM-10**: Methods-text generator. Deterministic templated params→prose (single-cell: software+versions,
  genome+annotation, QC thresholds, normalization, #HVGs/#PCs, integration+batch key, clustering algo+
  resolution, DE test+thresholds, ALL seeds) + Key Resources Table + DAS / Code-Availability statement
  (Nature + STAR styles). Optional LLM polish via txresbench assistants, **OFF by default** (artifact stays
  deterministic). Citations via the existing `citations`/`lit_search` CSL path.

- **ITEM-11**: Export bundle builder. A downloadable **BagIt-RO-shaped .zip**: `data/` (the walk's artifacts;
  a `fetch.txt` hole for large `.h5ad`) + generated `reproduce.py`/`.R` + env spec (rootfs digest + lockfile /
  `requirements.txt` / `renv.lock`) + `methods.md` + `manifest.json` (RO-Crate-SHAPED, fields map 1:1 onto
  WRROC `CreateAction`/`FormalParameter` so phase-2 upgrades in place) + `REPRODUCING.md` + `manifest-sha256.txt`.
  The annotated **`.h5ad`/`.rds` object** ships via P1's AnnData export codec (provenance references, never
  re-invents it). Bundle is a serialization of the ITEM-8 sub-DAG.

- **ITEM-12**: FE Reproducibility surface. Inspectable lineage-DAG panel (each run: tool+version+params+seed+
  inputs+outputs — a trust view, not a black box); **figure→run stamp** (run id + object hash + params +
  versions + seed) so "which run made this figure?" is answerable from the figure; a reproducibility-readiness
  checklist (seeds set? env pinned? inputs checksummed? versions captured?); one-click **Export**. Wire into the
  workbench IA: bottom-dock **Log/provenance** tab + top-toolbar **Export** button (WORKBENCH_IA §top/bottom).

- **ITEM-13**: `provenance_settings` singleton (DEC-SETTINGS — mandatory, not bare constants). Mirror
  `code_sandbox_settings`/`session_settings`: settings table + migration + read-at-use with cache invalidation
  + REST `GET/PUT /api/provenance/settings` gated `provenance::settings::{read,manage}` + `SyncEntity` + an
  admin card + bounds validation. Fields: verification enable/toggle, re-run time/size budget caps, bundle +
  certificate retention, Zenodo credentials (seam).

- **ITEM-14** *(phase 2)*: WRROC RO-Crate emitter. Upgrade `manifest.json` → valid `ro-crate-metadata.json` at
  the Provenance-Run-Crate profile (schema.org `CreateAction` per step, `FormalParameter` params, Bioschemas
  `ComputationalWorkflow`/`ComputationalTool`, PROV-convertible). Additive on ITEM-11's shaped JSON.

- **ITEM-15** *(phase 2, DEFERRED under scope)*: Optional Zenodo/DataCite DOI push (4-call REST: create → bucket
  upload → PUT metadata → publish; concept-DOI vs version-DOI; `relatedIdentifiers` → `IsSupplementTo` paper /
  `IsDerivedFrom` dataset / `IsVersionOf` re-runs). The one **external-service dependency** — keep the seam +
  settings creds, implement last (or defer past single-box MVP).

- **ITEM-16** *(phase 3)*: In-sandbox re-run verification badge (the differentiator; NO external dependency —
  the app owns the isolated headless network-clean sandbox). Re-run `run.sh` headless/no-network in the same
  rootfs against the bundle's `data/`, recompute the run's **set-valued output signature** (N `(output-id,
  hash)` for multi-output), diff regenerated vs recorded within **tolerance** (ARI≈1 on labels, `allclose` on
  embeddings — honest target = *statistical equivalence under a pinned environment*, not bit-exact). Stamp a
  **"Reproduced ✓"** certificate (own file-store artifact, `codecheck.yml`-style output manifest). Gated behind
  the ITEM-13 size/time budget.

## Sequencing

1. **Standalone-first (no P1 needed):** ITEM-2 (schema), ITEM-6 (rootfs full sha256), ITEM-13 (settings),
   ITEM-1 scaffold. Build + unit-test the graph + recipe model against fixtures.
2. **On P1 compute path:** ITEM-3 (capture seam) → ITEM-4 (inputs.json + resolver + closure) → ITEM-5 (root
   checksums) → ITEM-8 (walk/scoping). This is the "provenance-for-free byproduct" — the wedge.
3. **Export (Phase 1 MVP):** ITEM-9 (reproduce-script) → ITEM-10 (methods) → ITEM-11 (bundle) → ITEM-12 (FE).
4. **Selection loop:** ITEM-7 once P8's predicate DSL + P6/P7 brushing exist.
5. **Phase 2:** ITEM-14 (WRROC) → ITEM-15 (Zenodo, deferred/optional).
6. **Phase 3:** ITEM-16 (verification badge) — last, once the workflow is fully re-runnable headless.

## Decisions

- **DEC-P4-1 — graph ownership boundary (the one genuinely muddy line).** P1's catalog rows ARE the artifact
  nodes (content-hash keyed) + basic run + derivation edges ("the catalog's derivation edges ARE the provenance
  graph"). **P4 OWNS** the *enrichment* on top: `provenance_code_blobs`, run-node code/generator/env/seed
  columns, the `inputs.json` contract + resolver, `provenance_selections`, and the whole export/verify layer.
  P4 does NOT fork a parallel run/artifact/edge store *if* P1 already provides one — it extends it; if P1's
  catalog lands without run/edge tables, P4 owns `provenance_runs/artifacts/edges` per DEC-GRAPH. **Resolve with
  P1's owner before ITEM-2/3.**
- **DEC-P4-2** — Candidate D, MVP-first (phase 1 = Candidate A). Ship byproduct capture + one-click bundle
  first; standards manifest + DOI + verify badge are independent later slices.
- **DEC-P4-3** — passive auto-capture at the two chokepoints (compute + interaction), never explicit
  checkpoint (the effort tax kills the wedge).
- **DEC-P4-4** — store selection RECIPE (predicate + pinned input hash), not a materialized set;
  freehand-only = small id-list. §3.9 bitmask is runtime-only, never persisted provenance.
- **DEC-P4-5** — one code path: exported script = stored per-run code blob (never regenerated). Append-only;
  re-runs branch.
- **DEC-P4-6** — verification target = statistical equivalence under a pinned env (ARI≈1/`allclose`), NOT
  bit-exact. Frame honestly in UI + certificate.
- **DEC-P4-7** — Zenodo/DOI (ITEM-15) is the only external dependency → seam kept, deferred past single-box
  MVP; in-sandbox verify (ITEM-16) has NO external dep and stays in scope (budgeted).
- **DEC-P4-8** — methods = deterministic templated by default; LLM polish opt-in OFF.

## Risks

- **P1 foundation not built** — the whole capture layer blocks on P1's catalog + `JobRunner`→sandbox wiring.
  Mitigate: build ITEM-2/6/13 + fixtures standalone; keep the seam a thin trait P1 calls.
- **Graph-ownership double-build (DEC-P4-1)** — if P4 and P1 both create run/artifact/edge tables the data
  diverges. Mitigate: resolve the boundary before writing ITEM-2 migrations; one owner of the base triple.
- **Selection recipe ↔ P8 predicate grammar mismatch** — ITEM-7's persisted recipe must be exactly P8's DSL or
  the emitted `reproduce.py` predicate won't replay. Mitigate: recipe JSONB = P8's serialized predicate, no
  re-encoding.
- **Determinism of single-cell tools** — some are non-deterministic even seeded (threaded BLAS, UMAP) → the
  verify badge (ITEM-16) can false-fail. Mitigate: tolerance-based diff, `NUM_THREADS=1`, honest framing;
  ship the badge last.
- **Multi-output atomicity** — the run's output signature is set-valued (N hashes); a partial re-run that
  regenerates only some outputs must NOT pass. Mitigate: verify checks ALL N `(output-id, hash)` (DATA_MODEL
  §Provenance-implications).
- **Large `.h5ad` bundles** exceed a reasonable zip / re-run budget. Mitigate: `fetch.txt` hole + the ITEM-13
  size/time caps; verify gated behind budget.

## Effort

- Phase 1 (ITEM-1..13): **L** — the capture seam + graph + export bundle + FE panel are the bulk; ITEM-2/3/4/8
  (schema + chokepoint + inputs.json + walk) are the load-bearing core, ITEM-11/12 the widest surface.
- Phase 2 (ITEM-14, 15): **M** — RO-Crate emitter is additive; Zenodo is a bounded REST client (deferred).
- Phase 3 (ITEM-16): **M–L** — re-run + tolerance-diff engine; risk-heavy, ships last on a proven base.
- Overall gated by P1: ~none of the capture/export code lands until P1's compute path exists; the standalone
  schema/settings/rootfs slice (**S**) can proceed immediately.
