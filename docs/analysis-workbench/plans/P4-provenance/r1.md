# P4 — Provenance (graph capture + content-addressed code + selection-recipe + reproduce/export MVP)

**Round 1 (blind).** Scope: desktop + single-box. Build the lineage graph as a **zero-effort byproduct of the
compute contract**; the provenance graph **== the composition DAG** (`requires`/`produces` edges = `used`/
`wasGeneratedBy` edges). INTEGRATE live8's `feat/provenance` DESIGN (`DESIGN_CANDIDATES.md` §B1/§B3/§B3.1,
DEC-GRAPH) — do not reinvent it. This plan implements **Candidate D Phase-1 (== Candidate A, MVP)**: passive
auto-capture + a downloadable reproduce bundle (script + methods). **Defer** (seams open, no build): DOI/Zenodo,
full Workflow-Run RO-Crate, the in-sandbox re-run **verification badge**.

Grounding verified in code (`/data/pbya/txresbench/tmp/study-admin-wt`): `sandbox::service::run_analysis(state,
command, extra_mounts,…) -> SandboxRunResult` is the Linux compute chokepoint (stub on other OS);
`jobs::runner::JobRunner::spawn` is the seam `run_analysis` drops behind at integration; `jobs/seams.rs` is the
trait+Noop+`install_seams(OnceLock)` idiom to mirror; `study/core/extension/registry.rs` provides
`STUDY_EXTENSIONS` (distributed_slice) + `StudyExtension::on_study_deleted`. **No provenance module exists yet.**
`dataset` is a stub (uploads unwired, no checksum) → source-artifact roots are greenfield.

## Items

### Graph schema (provenance-owned — decoupled from the not-yet-built catalog; DEC-GRAPH)
- **P4-1**: `provenance_artifacts` (PROV *Entity*, node). Cols: `id uuid PK`, `study_id`, `content_hash` (sha256;
  merkle/manifest hash over a multi-file artifact — Zarr prefix, BAM+bai), `datatype` (text; P2 registry id),
  `storage_ref` (P1 working-store handle / `txresbench-file` id for uploads), `source_kind` enum
  `upload|run_output|reference`, `shape`/`metadata JSONB`, `created_at`. Unique `(study_id, content_hash)` for
  dedup. Roots (`upload`,`reference`) have **no** `wasGeneratedBy` edge.
- **P4-2**: `provenance_runs` (PROV *Activity*, run node / node). Cols: `id`, `study_id`, `job_id` (nullable — NULL
  for manual/interaction runs), `analysis_id` (the provenance unit; a multi-analysis job = N run nodes),
  `kind` enum `compute|selection|manual`, `tool`, `tool_version`, `params JSONB`, `seed`, `command` (`python
  script.py`), `code_sha256` FK→P4-4, `generator_id`+`generator_version` (the emitter that produced the script),
  `env_digest` (rootfs sha256 + lockfile hash), `started_at`,`finished_at`,`exit_code`,`status`, `acting_user_id`.
  Env is an **attribute of the run, never a data-input edge**.
- **P4-3**: `provenance_edges`. Cols: `run_id`, `artifact_id`, `role` enum `used|generated`, `output_slot` (text —
  maps a `generated` edge to the `produces`-manifest output id, for run→N-artifact fan-out), `created_at`. **Run→
  N-artifact fan-out** = N `generated` rows per run (produce-atomically); downstream `used` binds one specific
  output (consume-individually).
- **P4-4**: `provenance_code_blobs` — content-addressed code store. Cols: `sha256 PK`, `language`, `source TEXT`,
  `created_at`. Dedup by hash; **Postgres, not `txresbench-file`** (code is KB-scale graph metadata). `runs.code_sha256`
  references it. Ordering guarantee: **generate → hash → store blob → run → record run node** (a FAILED run still
  has its exact code captured).
- **P4-5**: `provenance_reference_resources` — pinned external roots (reference genome+annotation version,
  reference atlas, gene set). Cols: `id`,`kind`,`name`,`version`,`accession/doi`,`content_hash`,`created_at`.
  First-class versioned root nodes (journals require reporting them). Referenced as an `artifact` with
  `source_kind=reference`.
- **P4-6**: Migrations under `provenance/migrations/` (sqlx, host-owned kernel schema; compile-time macros need
  build DB `:54321`). Indexes: edges on `(artifact_id,role)` + `(run_id,role)` for the recursive walk; artifacts
  on `(study_id, content_hash)`.

### Capture seam (the byproduct mechanism — two chokepoints, one graph)
- **P4-7**: `ProvenanceCapture` trait + `NoopProvenanceCapture` default + `install_capture(OnceLock)` — mirrors
  `jobs/seams.rs` exactly. Methods: `record_run(RunRecord) -> run_id`, `record_edges(run_id, used[], generated[])`,
  `store_code(source,lang) -> sha256`, `record_reference(...)`. The generic `jobs` module stays reusable — it emits
  through this seam, it does NOT become a DAG.
- **P4-8**: **Compute chokepoint capture** — a `ProvenanceJobRunner` decorator wrapping the P3 `JobRunner`/
  `run_analysis`. Before spawn: resolve declared logical inputs (`upload_id`/`analysis_output_id`/
  `reference_resource_id`) → record `used` edges (**closure enforcement**: reject a job whose input isn't a known
  upload/artifact/reference — closes the "input from nowhere" hole). After exit: read the P3 **`produces`
  manifest** (`/outputs/manifest.json`), content-hash + ingest each declared output as its **own** artifact node
  (fan-out), record `generated` edges keyed by `output_slot`, and write the run node (`code_sha256`, generator
  version, `env_digest`, seed, params, timing, exit). Ancillary files (logs/temp) attach as run metadata, **not**
  graph nodes.
- **P4-9**: **Interaction chokepoint capture** — `POST /api/provenance/selections` (+ generic
  `POST /api/provenance/actions`): the Explorer/host calls a "record selection/action" API. Records a
  `kind=selection|manual` run node whose `used` edge is the exact input artifact (by content hash) and whose
  `generated` edge is a **cell-set recipe artifact** (below). The second capture source alongside compute; both
  emit into the one graph. Registry-shaped (`INTERACTION_ACTIONS` open slice) so future manual actions (annotate/
  group/subset — DATA_MODEL §B2 catalog) plug into the SAME seam without a retrofit — but **only `selection.*` is
  built this round**; the rest reserve vocabulary only.

### Content-addressed code + path-agnostic inputs.json (the "code that ran == code exported" trick)
- **P4-10**: **inputs.json contract** — a tiny path-binding manifest mapping the script's logical input/output
  *slots* → paths. **Derived, not authoritative** (canonical provenance = the graph edge run-`used`-artifact-by-
  id+hash; inputs.json materializes that edge into a path for ONE environment). Generated fresh: slots→sandbox
  mounts at run time, slots→`data/` at export → **byte-identical script** both places, no path rewriting. Params +
  seed are baked into the **script body** (not inputs.json), so `code_sha256` fingerprints "this template + these
  exact params" (a param change → new script → new run node); `runs.params` is the queryable mirror.
- **P4-11**: **Code-blob source = the extension's staged sandbox entry** (CORRECTION to live8's app-emits-scanpy
  assumption — see Decisions). For a built-in/extension analysis (P5/P11) the "captured code" is the extension's
  `compute/*.py`/`.R` entry bytes (already content-addressable) + the generated `inputs.json` + a harness preamble
  (seed + `OMP/OPENBLAS/MKL_NUM_THREADS=1` + `read_input`/`write_output` helpers reading `inputs.json`). Hash the
  assembled script → `code_sha256`.

### Selection-as-recipe (predicate + pinned input hash — size-independent of cell count)
- **P4-12**: A **cell-set is stored as a RECIPE, never a materialized set** (studies reach ~10M cells; a packed
  mask is ~1.25 MB *each*). A `selection` run node stores: the **predicate** (the P8 cell-set DSL expression —
  polygon+embedding-hash / `{col,op,val}` / clustering-labels / set-algebra operand-refs+op) + the **pinned
  content-hash of the input artifact** it was drawn on (~1 KB, O(1) in N). Reproduces **exactly** because the
  input is pinned → deterministic replay, no drift, no stored fallback set. Emitted code blob = the predicate as
  runnable code (`sel = points_in_polygon(ad.obsm['X_umap'], poly)`); `points_in_polygon` ships as a harness
  helper. The materialized bitmask is **runtime-only** (transient, re-derived on demand) — NOT persisted
  provenance.
- **P4-13**: **Freehand** (individual hand-picks) is the ONLY case storing identities — inherently small, a small
  explicit id-list (`ad.obs_names.isin([ids])`). Anything large is always predicate-expressible.
- **P4-14**: Wire `api.selection.setByPredicate` / the annotation `assign` (PLATFORM §0.4.1) to call P4-9 so the
  human-lasso / AI-emitted / provenance representations are ONE (the shared recipe). (Consumes P8's DSL type; P8
  builds the evaluator.)

### Reproduce / export MVP (script + methods text)
- **P4-15**: **Backward reachability walk** — a Postgres `WITH RECURSIVE` from a target artifact/run over
  `used`/`generated` edges → the minimal sub-DAG (closure to roots). Export scope = which root you walk from:
  single analysis/figure (default), a set, or the whole study (union of leaf closures). Sibling outputs of a
  multi-output run that the target didn't `used` are **excluded from carried data** but still regenerate on re-run
  (produce-atomically). Used-vs-dead outputs fall out of reachability.
- **P4-16**: **Bundle assembler** — serialize the sub-DAG into a downloadable bundle (BagIt-RO-shaped, desktop =
  local zip): per-step scripts (fetched from `code_blobs` by `code_sha256`, topological order) + a `run.sh` driver
  (the Code-Ocean capsule shape) + `data/` (the walk's artifacts, read from P1 object store) + a bundle-relative
  `inputs.json` + `manifest.json` (RO-Crate-**shaped bespoke** JSON, upgradeable in place to full WRROC in a later
  phase) + `methods.md`.
- **P4-17**: **Methods text (templated, deterministic)** — assemble `methods.md` from each run node's
  `methodsText(params)` (the `AnalysisContribution.methodsText` hook, PLATFORM §1.2) in topo order + tool versions
  from `env_digest`. LLM-assisted polish **deferred / off** (DEC-METHODS default).
- **P4-18**: REST `GET /api/provenance/graph?study_id` (inspectable DAG), `GET /api/provenance/runs/{id}`,
  `POST /api/provenance/export {target, scope}` → bundle. Gated `provenance::read` / `provenance::export`.
- **P4-19**: **Deferred seams (declare, don't build)**: a `verify(bundle) -> Reproduced?` hook signature +
  `manifest.json` fields (`conformsTo`, verification slot) left open so Phase-2 WRROC/DOI and Phase-3 in-sandbox
  re-run badge slot in without a schema change. Reuses the same `sandbox::run_analysis` + `run.sh` that the bundle
  already ships (byte-identical) — no rework at that phase.

### Study-extension integration + frontend
- **P4-20**: The `provenance` module registers `#[distributed_slice(STUDY_EXTENSIONS)]` with an
  `on_study_deleted` hook that cascades `runs`/`artifacts`/`edges`/`code_blobs`/`reference_resources` for the study
  (via the shared `delete_study_with_extensions` chokepoint, live8). `on_study_duplicated` deep-copies the graph
  (deferred-nice; MVP may no-op with a flag).
- **P4-21**: Sync entity `ProvenanceRun` (owner/study-scoped, `Create` emitted from the capture task,
  `origin=None`) so a shared workbench's provenance panel refreshes live (notify-and-refetch).
- **P4-22**: Frontend `provenance` study-extension (`STUDY_SLOTS`, `ui/src/modules/provenance/`): a
  **"Reproducibility" panel** (inspectable lineage graph + figure→run stamp resolver + an **Export** button) +
  a store (`defineStore`, subscribes `sync:provenance_run`) + `provenance::read` gating. Right-dock semantic slot.
- **P4-23**: Permissions `provenance::{read,export}` granted to the Users group / study editors+viewers (viewer
  read-only); admins via `*`. Migration for the grant.

## Dependencies

- **P3 compute-scheduling (KEY DEP)** — provenance capture wraps P3's `JobRunner`→bwrap wiring and reads P3's
  **`inputs.json` / `/outputs/manifest.json` contract**. P4 is *defined as* the byproduct of that contract, so the
  contract shape is a hard interface. P3 owns the sandbox I/O contract; P4 owns run-node/edge capture + code-blob +
  inputs.json *generation from graph edges*.
- **P1 data-foundation (KEY DEP)** — the working store + `analysis_results` catalog + local object store +
  content-hashing at ingest + authed byte serving. Artifact `storage_ref`/`content_hash` (P4-1) come from here; the
  export bundle's `data/` reads artifacts from here.
- **P2 datatype-system** — artifact `datatype` id + the multi-file merkle/manifest content hash per artifact.
- **P8 interaction-dsl** — the cell-set predicate DSL that P4-12 stores as the selection recipe (P8 builds the
  evaluator; P4 persists its expression + pinned hash).
- **P10 study-substrate (live8, already built)** — `STUDY_EXTENSIONS`, sync `publish`, permissions grant,
  `delete_study_with_extensions` cascade chokepoint.
- **rootfs** (exists) — the env fingerprint sha256.
- **DEC-FOUNDATION**: P1+P3 are the platform critical path; P4 **cannot land until they exist**, but the
  provenance-owned schema (P4-1..6) is authorable now against the decoupled tables.

## Decisions

- **DEC-P4-1 (adopt live8 DEC-GRAPH)**: provenance-owned `provenance_runs`/`_artifacts`/`_edges` triple +
  `_code_blobs` + `_reference_resources`; do NOT turn `jobs` into a DAG (keeps jobs reusable).
- **DEC-P4-2**: code → content-addressed **Postgres** blobs (not `txresbench-file`, not bespoke); data artifacts → P1
  object store; graph → Postgres.
- **DEC-P4-3 (multi-output)**: one run FANS OUT to N artifact nodes (N `generated` edges w/ `output_slot`);
  **reproduce unit = run** (produce-atomically), **consume unit = artifact** (consume-individually); run
  output-signature = set of `(output_slot, hash)`.
- **DEC-P4-4 (code source correction)**: the captured code is the **extension's staged sandbox entry bytes** +
  generated `inputs.json` + harness preamble — NOT an app-side scanpy template (live8 predates the extension-
  platform model where the extension ships `compute/*.py`). Still hashed → `code_sha256`; live8's "one code path /
  byte-faithful export" property holds. `generator_id/version` = the extension id+version.
- **DEC-P4-5**: selection = **recipe** (predicate + pinned input hash), bitmask runtime-only; freehand = id-list.
- **DEC-P4-6 (closure)**: enforce the 3-source-kind invariant at the chokepoint (reject inputs not known as
  upload/artifact/reference) — the roots MUST carry content hash (dataset upload is greenfield → add checksum).
- **DEC-P4-7 (scope)**: MVP = Candidate-D Phase-1 (auto-capture + downloadable script/methods bundle,
  RO-Crate-shaped bespoke JSON). **Defer** DOI/Zenodo, full WRROC, in-sandbox verification badge — seams declared
  (P4-19), upgradeable in place.
- **DEC-P4-8**: export manifest = backward closure from the target root only (not all jobs / sibling analyses).

## Risks/unknowns

- **R1 (contract co-ownership, highest)**: the `inputs.json`/`produces`-manifest shape is co-owned with P3.
  Divergence breaks capture. Mitigation: P3 defines the on-disk sandbox I/O contract; P4 defines run-node/edge
  capture + code-blob; agree the manifest JSON schema at the P3↔P4 boundary in round-2 consolidation.
- **R2**: multi-file artifact content-hashing (Zarr prefix, BAM+bai) — a merkle/manifest hash defined by P2's
  storage layout; if P2 picks Zarr-as-object, the hash is over the chunk manifest. Coordinate with P2.
- **R3 (foundation)**: P1+P3 are proposals/stubs (DEC-FOUNDATION). Provenance-owned schema decouples capture, but
  end-to-end capture can't run until the JobRunner→sandbox path is real. Author schema+seam first; wire capture
  when P3 lands.
- **R4**: the interaction-action registry is intentionally OPEN but only `selection.*` is built this round — risk
  of over-building the vocabulary. Mitigation: reserve types, build one.
- **R5**: `on_study_duplicated` graph deep-copy is nontrivial (re-point storage refs) — MVP may defer to a no-op
  behind a flag; note as SDK gap.
- **R6**: methods.md quality depends on each analysis providing `methodsText` — extensions that omit it get a
  generic sentence. Acceptable for MVP.
