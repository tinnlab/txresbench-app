# P8 — Interaction primitives + cell-set predicate DSL (Round 1, blind)

Scope: the SHARED interaction primitives (`api.selection` / `api.brush` / `api.pick`), the **cell-set predicate
DSL** (a small, safe, bounded expression language over per-cell values → a bitmask) + the host **predicate
evaluator**, and **selection-as-recipe** wiring (predicate + pinned input hash → provenance). Desktop + 1-box;
the evaluator runs **in-process (client/host-JS)**; heavy computed features are deferred to a sandbox analysis
that produces a `metadata-column` artifact the DSL merely *references* (never computes).

Grounded in code that already exists (live3 `feat/visualization`):
- `viz-core/data/selection.ts` — `IndexMask` (packed `Uint32` bitmask; `union`/`intersect`/`difference`/`count`/
  `has`/`set`/`clear`, `popcount32`) + pure hit-tests `selectInBox` / `selectInPolygon` / `bboxCandidates` /
  `polygonBoundingBox`. **This IS the cell-set + set-ops + lasso engine** — do not re-invent.
- `viz-core/selection/SelectionController.ts` — ordered AREAS (rect/polygon) each with a combine mode
  `add|subtract|intersect`, folded into a combined `IndexMask` via the bitmask set-ops (the legacy
  Union/Intersection/Custom model). The area list IS a proto-recipe.
- `adapter/Coordination.store.ts` — the Vitessce-style shared store: `pointSelection: Uint32Array`,
  `selectionOrigin`, `highlight`, `geneSelection`, `setSelection(cellId, indices)` / `clearSelection` /
  `setHighlight`. **This is the shared selection/brush/pick substrate `api.*` promotes to the public API.**
- legacy `NewDEForm.tsx` `getCellIds({sampleIds, clusters, metadata, annotations, selectedCellIds})` — the
  compound cell-set builder with per-filter **include/exclude** (`isExcluded`) intersect/andnot semantics + a
  **live cell-count preview** + overlap detection. This is exactly what the DSL categorical encoder generalizes.

## Items

- **ITEM-1 — `CellSet` public contract** (`@txresbench/workbench-api`). Promote live3 `IndexMask` as the canonical
  `CellSet`: a packed-`Uint32` bitmask over the **dense study view-index** axis (§5 canonical `system_cell_id`).
  Keep `union/intersect/difference/count/has`; add `toDurableIds()` / `fromDurableIds()` `(sample,local_index)`
  round-trip so a mask survives axis re-materialization + cross-analysis alignment (NA outside covered cells).
  Zero-copy `Uint32Array` view (`toIndices()`) for deck.gl + `Coordination.pointSelection`.
- **ITEM-2 — DSL AST + TS types.** The predicate node union: **leaf terms** — `{gene, layer?}`, `{obs}`,
  `{col}` (a `metadata-column` artifact), `{clustering, id}` (categorical codes), `{lit}`, and
  `{reduce: 'median'|'mean'|'quantile'|'mad'|'std'|'min'|'max'|'count', of: <term>, p?}`; **comparisons** —
  `gt/gte/lt/lte/eq/neq/between/in/notin/isna`; **boolean/set ops** — `and/or/not/xor/andnot`; and a
  **geometric** node `{geo:{embedding, polygon|rect, mode}}` (ITEM-9). JSON round-trip; the §0.4.1 worked shape
  (`{gt:[{gene:ABC,layer:lognorm},{reduce:median,of:{gene:ABC,layer:lognorm}}]}`) is the acceptance fixture.
- **ITEM-3 — DSL JSON-schema + semantic validator.** A published `predicate.schema.json` (part of the API
  contract, like the manifest schema §3) validates structure; a semantic pass validates references (gene in
  `var`? obs column exists? layer exists? `metadata-column` artifact present?) and **bounds** (AST depth ≤ D,
  node count ≤ N, reduction count ≤ R) → typed errors (`UnknownGene` / `UnknownColumn` / `TooComplex` /
  `TypeMismatch`). One validator, run **both client (pre-apply) and server (pre-persist)**.
- **ITEM-4 — Operator/feature vocabulary descriptor.** A machine-readable catalog `{operators[], reductions[],
  leafKinds[]}` with arity + semantics + doc strings, exported for THREE consumers: the `cell-set-selector`
  widget builder (ITEM-8), the **MCP resource** the AI reads (§0.4.2 "cell-set DSL operator → added to the DSL
  vocabulary the AI reads"), and human docs. **Extensible**: a produced `metadata-column` (new `{col}`) or a
  contributed operator appends to it — this is how an extension "enriches the AI's world model" (§0.4.2).
- **ITEM-5 — Column resolver.** Binds DSL leaf refs to the P1 data API: `data.geneColumn(gene,layer)` (sparse
  CSC slice `{row:Uint32Array, value:Float32Array}` — O(nnz)), `data.obs(col)`, `data.clustering(id)`
  (`{codes,categories}`), and a `metadata-column` artifact read. Produces a per-cell **dense view** with
  **sparse-absent = 0** (layer-correct for lognorm/counts) + an **NA mask** (cells outside covered set). Memoized
  per `(ref, layer, axisVersion)`.
- **ITEM-6 — Reduction kernels.** O(n) `median` (quickselect, no full sort), `mean`, `quantile(p)`, `mad`, `std`,
  `min/max`, `count` over the resident column (optionally selection-restricted for "median within selection").
  NA-aware (skip NA cells). Scalar result cached per `(term, axisVersion, restrictMask?)`.
- **ITEM-7 — The predicate evaluator (in-process TS) — the host's "predicate evaluator" (§0.4.1).** Recursive
  eval: term → column (ITEM-5); reduce → scalar (ITEM-6); comparison → a per-cell `IndexMask`; boolean/set op →
  `IndexMask.union/intersect/difference` (reuse). **Pure, bounded, deterministic**; NaN/NA cells are **never
  selected**. Returns a `CellSet`. This is the single evaluator shared by AI-applied, widget, and lasso paths.
- **ITEM-8 — Categorical/compound predicate encoder + live count.** Generalize legacy `getCellIds` (cluster /
  metadata / annotation / sample, each with include/exclude) into DSL: a base `in` over sample ids, then per
  filter `intersect`(include) / `andnot`(exclude). The `cell-set-selector` widget (P6 chrome) emits a
  **predicate**, not a frozen id list; a **partial eval** gives the legacy **live cell-count preview** +
  cross-group overlap check. This is the "DE group1/group2 builder as a recipe" resolution.
- **ITEM-9 — Geometric-lasso → predicate compiler.** A `{geo:{embedding:id, polygon|rect, mode}}` node; the
  evaluator resolves the embedding coords via the data API and runs live3 `selectInPolygon`/`selectInBox`
  (+ `bboxCandidates` narrowing) → mask. So a **human lasso persists as a recipe** (embedding id + polygon +
  input hash), reproducible + scale-safe (§0.6 "selection is a RECIPE, never a materialized cell set"). Bridges
  `SelectionController`'s area list into DSL nodes (each area = one `geo` node folded by its combine mode).
- **ITEM-10 — `SelectionRecipe` model + input-hash pinning.** `{ predicate, inputs: {ref → {artifactId,
  contentHash}}, axisVersion, evaluatorVersion }`. Resolve every leaf ref to a catalog artifact + its
  **content hash** (P1/P2 catalog), so re-evaluating on the same pinned inputs yields identical cells
  (content-addressed reproducibility). The recipe — not the bitmask — is what provenance stores.
- **ITEM-11 — `api.selection` service.** Wrap `Coordination.store` as the public
  `selection: { current():CellSet; useCurrent(); onChange(cb):Disposable; set(CellSet);
  setByPredicate(Predicate):Promise<CellSet>; recipe():SelectionRecipe|null }`. `set` writes
  `pointSelection`; `setByPredicate` validates (ITEM-3) → evaluates (ITEM-7) → builds+stores recipe (ITEM-10) →
  sets shared state. This is the AI's hand AND the annotation panel's `api.selection.useCurrent()` (§4.4) —
  one shared cell-set for annotation / DE / subcluster.
- **ITEM-12 — `api.brush` service.** A brushed 1-D range `{ term, lo, hi }` on an axis/histogram (a QC
  threshold / gate bound). Is itself a `between` predicate (composes into the DSL). Stored on Coordination.store
  (`brush` field, new); `useCurrent`/`set`/`onChange`. Consumed by `threshold-on-histogram` (§4.3 widget).
- **ITEM-13 — `api.pick` service.** The clicked/hovered cell — `{ viewIndex, durableId }`. Promote
  Coordination.store `highlight` (index) + add durable id; `useCurrent`/`set`/`onChange`. Trajectory
  start/end / tooltip origin (§4.4).
- **ITEM-14 — MCP `selection.setByPredicate` tool contract.** The tool input schema = the DSL JSON-schema
  (ITEM-3); `safety: read-run` (select-only can't harm; the *assign* is the separate gated action §0.4.1).
  Server validates + resolves hashes + records the recipe, then a **sync event** materializes the mask on the
  client (human + AI co-drive one state §0.4). The generation of this tool is P9; P8 owns the schema + handler.
- **ITEM-15 — Server-side validate + hash-resolve + recipe persistence hook (Rust).** In the workstore/selection
  submodule: validate the predicate JSON against the schema (ITEM-3, mirrored), resolve refs → catalog artifact
  content hashes (P1), and persist the `SelectionRecipe` as a **provenance selection run-node** (P4). **No Rust
  re-evaluator in scope** — reproduce runs through P4's emitted-code / sandbox path; a headless Rust evaluator
  is flagged optional (Risk R4).
- **ITEM-16 — Selection origin + self-echo + fan-out.** Reuse `selectionOrigin`: tag a predicate-set selection
  `ai` / `widget` / `lasso` / `panel:<id>` so overlays + linked panels fan out without a write-back loop (the
  existing `setSelection` origin mechanism). AI-driven `setByPredicate` emits a study-scoped sync signal (§0.5).
- **ITEM-17 — DSL-vocabulary + data-schema as MCP resources.** Own the *content* of two resources the AI reads
  before emitting a predicate: the operator vocabulary (ITEM-4) and the study's `var`/`obs`/`metadata-column`
  schema (does gene `ABC` exist? §0.4.1). Exposure/generation is P9; the projection functions live here.
- **ITEM-18 — Predicate → methods/human text.** A renderer `predicate → "cells where lognorm(ABC) > median(ABC)"`
  for the methods paragraph + provenance display + the widget's read-back label (§0.4.1 / §0.6 reproduce-export).
- **ITEM-19 — Tests.** Unit: AST JSON round-trip; **evaluator parity vs a brute-force full-N scan oracle**
  (the CPU parity oracle pattern already used in `selectionNarrowing.test.ts`); reduction kernels vs numpy-style
  fixtures; bounded-reject (`TooComplex`); NA + sparse-zero semantics; **geo→predicate parity vs live3
  `selectInPolygon`**; **categorical encoder vs legacy `getCellIds` oracle** (port a fixture from `NewDEForm`).
  Integration: `setByPredicate` → recipe persisted → re-eval yields byte-identical mask; MCP tool schema
  round-trip; input-hash stability. Property battery: eval determinism + hash stability under reorder.

- **P5 contribution-api** — `api.selection`/`brush`/`pick` are fields on `WorkbenchAPI`; P8 defines their types,
  P5 assembles the runtime object.
- **P6 workbench-shell** — hosts the `cell-set-selector` / `threshold-on-histogram` widget *chrome*; P8 supplies
  the builder→predicate encoder + count evaluator those widgets call.
- **P9 ai-mcp** — generates `selection.setByPredicate` as a tool + exposes the vocabulary/data-schema resources;
  P8 owns the schema + handler + resource content (ITEM-14/17).

5. **Server + AI seam** (needs P1 catalog + P4 recipe node): ITEM-15, ITEM-14, ITEM-17.

Critical path: **P1 data API + catalog hashes** → ITEM-5/6/7 → ITEM-10/11 → ITEM-15. The pure contract layer
(step 1) can start immediately, blind of P1.

## Decisions

- **DEC-1 — Canonical evaluator = in-process TS (client/host-JS), single implementation.** Columns are already
  resident for coloring (§0.4.1); the widget, human-lasso, and AI-applied paths all funnel through the same TS
  evaluator. The server does **validate + hash-pin + persist**, not evaluate. Reproduce uses P4's emitted-code.
  (A Rust evaluator is deferred — Risk R4.)
- **DEC-2 — Selection stored as RECIPE, never a materialized cell list** (§0.6). Even a human lasso persists as
  `{geo, embedding, polygon, input hash}`. Scale-safe (10⁶ cells) + reproducible.
- **DEC-3 — Heavy features are NOT in the DSL.** A 500-gene signature / neighborhood stat is a **sandboxed
  analysis → `metadata-column` artifact**; the DSL only references that column (`{col}`). Keeps the evaluator a
  fast, safe O(n) filter over resident values (§0.4.1). The bound in ITEM-3 enforces this.
- **DEC-4 — Bounded, no arbitrary code.** Max AST depth D=32, max nodes N=256, max reductions R=16 (tunable);
  no function calls, no loops, no host access beyond the declared leaf refs. An AI-emitted select **can't harm**
  — it only selects; assign is separate + gated (§0.4.1).
- **DEC-5 — Sparse-absent = 0 in the value domain of the layer.** For lognorm/counts a gene column's non-nnz
  cells are genuine zeros (expressed nowhere), so a `> median` correctly includes/excludes them; NA is reserved
  for cells *outside the covered axis*, which are never selected. This is the correctness lynchpin of ITEM-5.
- **DEC-6 — `brush` and categorical filters are DSL sugar, not separate models.** `api.brush` = a `between`
  node; a categorical widget filter = `in`/`andnot` nodes. One representation → one evaluator → one recipe.
- **DEC-7 — Reuse live3, don't fork.** `IndexMask`/`selectInPolygon`/`SelectionController`/`Coordination.store`
  are the substrate; P8 adds the DSL + evaluator + recipe + `api.*` wrappers around them.
- **DEC-8 — `CellSet` is over the dense view-index; durable ids are the persistence/alignment form.** The recipe
  and cross-analysis alignment use `(sample,local_index)`; the hot path uses the dense bitmask.

## Risks / unknowns

- **R1 — Column residency for AI-driven selection.** The AI calls server-side, but the canonical evaluator is
  client-side; if no client is attached (headless AI run) the mask can't materialize. Mitigation: record the
  recipe server-side regardless; materialize on the next client attach (recipe is the source of truth). Confirm
  the co-drive model with P9. *(Open.)*
- **R2 — Input-hash resolution needs P1 catalog content-hashing.** If P1 doesn't content-hash artifacts, the
  recipe's reproducibility guarantee weakens to `artifactId@version`. Coordinate the hash contract with P1/P2.
- **R3 — Reduction correctness at scale (median of 10⁶).** Quickselect O(n) is fine in-process, but a
  selection-restricted reduction over a sparse gene column needs care (which cells count as 0 vs NA). Covered by
  DEC-5 + parity tests, but it's the subtlest correctness surface.
- **R4 — No server-side Rust evaluator.** Reproduce/headless verification relies on P4's emitted-code path. If a
  future need requires host-side evaluation (e.g. server-rendered exports), a Rust mirror of ITEM-7 is a
  follow-on (medium lift; the AST + schema are shared).
- **R5 — Categorical encoder parity with the legacy builder.** The legacy `getCellIds` include/exclude ordering
  (intersect-then-andnot per filter, sample-id base) has subtle overlap semantics; the oracle test (ITEM-19)
  must port real fixtures or a behavioral drift ships silently.
- **R6 — DSL versioning.** `evaluatorVersion` in the recipe must gate re-eval; a semantics change (e.g. NA
  handling) invalidates old recipes' reproducibility. Need a migration/version-compat policy (defer, but stamp
  the version now).
- **R7 — Geometric recipe stability under embedding recompute.** A `geo` recipe pins the embedding artifact
  hash (DEC-2), so re-running on a *new* embedding is correctly a different recipe — but the UX of "your lasso
  is stale because the embedding changed" needs a surfaced signal (P6/P7).
